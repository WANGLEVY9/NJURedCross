# 页面加载优化线上验证

## 验证范围

日期：2026-10-10。公开生产地址：`https://njuredcross.cn`。

优化前代码为 `b2d639b`，首轮部署为 `4b80bcc`。对桌面 1440px 和手机 390px 视口使用 Chromium，先创建无缓存浏览器上下文，依次完整访问活动广场、主页、活动广场、内建、物资和宣传页面。活动广场以献血车汇总入口实际可见为完成条件；其他页面仅测标题出现，不代表其全部业务数据已加载。

## 活动列表实测

| 场景 | 优化前 | 首轮部署后 |
| --- | ---: | ---: |
| 桌面首次完整进入活动广场 | 34.921 秒 | 4.405 秒 |
| 手机首次完整进入活动广场 | 11.564 秒 | 4.240 秒 |
| 桌面再次完整加载活动广场 | 4.379 秒 | 1.753 秒 |
| 手机再次完整加载活动广场 | 5.788 秒 | 2.744 秒 |
| 桌面从宣传广场站内返回活动列表 | 1.792 秒 | 0.005 秒 |
| 手机从宣传广场站内返回活动列表 | 3.805 秒 | 0.003 秒 |
| 公共活动 JSON 响应正文传输体积 | 62,293 字节 | 4,821 字节 |

站内返回的数据为短期已有快照，后台仍会重新请求；几毫秒的呈现时间不是后台查询耗时。线上独立 HTTP 请求验证活动列表 gzip 响应约 335ms、工作流公共列表约 367ms；它们是单次采样，不是延迟保证。

首轮桌面首次活动页面的资源正文合计从约 520KB 降至 113KB；手机约 520KB 降至 118KB。该指标截至列表可见时统计，受异步资源加载顺序影响。手机首次进入还发现预加载完成后又请求一次活动列表，后续修正让首次挂载直接消费预加载结果，站内返回再强制刷新。

## 其他页面与限制

各公开页面的标题加载测量未一致提升：主页桌面 1.937→2.943 秒、手机 3.433→2.515 秒；物资桌面 2.501→2.665 秒、手机 1.249→1.588 秒。宣传和内建标题在此次采样中更快，但不可据单次样本证明长期性能提升。共享资源压缩和预加载已经生效；私人收件箱、会员中心和管理员业务的改进由合成回归验证，并未为了测速在生产创建报名或修改真实会员记录。

测试是在实际公网进行，网络状态、外部数据源和服务器缓存均可能影响结果，特别是优化前桌面 35 秒样本包含明显的首次资源等待。需要把传输体积、具体等待链路改进与单次墙钟时间分别理解。

- 首轮部署的 146 个运行文件与发布清单哈希一致，生产 `.env` 哈希保持不变。

- 生产站内切换测试无浏览器脚本异常，两个视口均无页面横向溢出。
- 实际响应确认 JS/CSS、公共列表使用 gzip；匿名会话响应没有进入公共压缩白名单。
