# 管理端 P05 / P06：跨模块工作区与回归

## 范围与依据

2026-10-14，基于 main `baaf320`，按宣传管理、内建管理、物资管理、运营总览顺序实施，再做跨模块验收。用户附件的本地路径已不可用，本轮依据会话中保留的完整 P05 / P06 要求、现有设计文档和真实组件实现；未宣称重新读取缺失附件。

所有交互测试使用隔离合成服务。未迁移生产表、未修改审批/库存/举报/权限状态机，未发送真实邮件，也未写入真实志愿者记录。

## 审计与改造

| 模块 | 原问题 | 本轮设计与交互 |
| --- | --- | --- |
| 宣传管理 | 六列看板空列占位，审核内容与决策长距离分离 | 默认可检索分页任务列表；可切回按非空阶段自适应的看板；所有阶段及数量始终可筛选。宽版审核工作区左右区分作品与来源、审核链/检查项/意见/最终决策 |
| 内建管理 | 少量数据仍使用大统计卡；生日状态过滤重复请求 | 紧凑统计条、共享记录列表；生日人员/投稿/举报使用已读取数据过滤；详情与原有拉黑、退出、恢复操作保留；区分加入、审核、送达 |
| 物资管理 | 六张统计卡争夺注意力；任务组显示前十条后缺少继续入口 | 优先展示待审批、逾期、异常归还、低库存；库存总量折叠汇总；任务按紧急程度排列；全部申请入口与状态过滤；台账分页检索 |
| 运营总览 | 空趋势与空分布占据大型面板；三个区域重复读取待办 | 待办优先、简洁真实空状态、自适应网格；并发待办读取合并为一个请求，手动刷新同步更新三个相关区域 |

共享 `recordTable` 在这些模块内启用每页 25 条，降低可见 DOM 数量；搜索和排序重置页码。手机以带标签的记录摘要替代宽表，完整信息仍通过详情打开。分页在浏览器端进行，不宣称减少服务端全量查询成本。

统计使用立即可读的真实数值，修复异步数据区域错过数字动画初始化、一直显示 0 的问题。新模块样式归属 `admin.css`；旧 cube/mobile/experience 指标卡规则限定在旧模块，避免叠加覆盖。截图检查发现手机表格仍继承 640px 最小宽度，已修正，并新增表格自身宽度断言。

## 业务边界

- 宣传审核继续使用原多级审核、意见 Word、人工排期及结果登记 API；进入详情不执行写入。
- 生日与早安晚安继续使用原审核、举报与黑名单规则；早安晚安服务端状态检索保留真实请求。
- 物资审批确认、幂等键、库存校验、损耗结算及流水代码未改变。
- 刷新失败保留可读旧列表并显示错误；401/403 清空旧数据。局部状态过滤不会重新读取整表。
- 活动 P03 通知编辑及 P04 名单/签到/时长流程作为回归范围，未改变其审批或录入逻辑。

## 限制

本轮减少了重复读取、列表渲染及无效布局，但没有生产网络延迟的前后基准，不声称生产接口获得固定倍数提速。后端全表读取、真实设备弱网体验及人工多级审核耗时仍需独立测量。完整业务写入由隔离测试验证；上线验证采用只读方式。
