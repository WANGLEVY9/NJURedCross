# 内建广场与献血车加载优化

## 原因与证据

匿名生产接口修复前单次测量（含客户端网络耗时）：功能检查 2.586 秒，献血车班次 4.335 秒，首页概览 1.035 秒。这是诊断样本，不是稳定的性能 SLA。

内建入口在返回页面之前等待功能检查；启用新版后，已登录用户还必须等待个人参与资料及祝福读取。生日结构检查未缓存，生日和早安晚安分别读取同一 Base 的元数据。献血车日历单独读取流程活动、报名与源排班，未复用活动广场已有的公开展示快照。

## 修改

- 内建页面立即呈现标题与明确的加载状态；功能检查结束后呈现对应版本，不提前开放未经验证的功能。
- 新版公开内容不再等待私有记录；状态加载时禁用报名按钮，结束后更新真实参与状态。离开页面后不再更新已销毁的内容。
- 内建个人状态改用 `/api/portal/me?view=warmth` 的账号受限投影，不再额外扫描活动报名、项目、场次和宣传投稿；会员中心完整接口保持原行为。只返回本人参加记录，无全局私有缓存。
- 两个温暖计划共享一次元数据读取与 30 秒短期缓存；失败关闭功能且不缓存连接异常。后台预热只读，不发邮件或写表；写入所需生日结构检查仍直读权威源。
- 活动广场与日历共享服务端流程快照：10 秒新鲜期、额外 20 秒内异步刷新，到期必须重新读取；既有活动后台刷新覆盖此快照。成功业务写入清空缓存。快照仅用于展示，报名、身份、签到和时长处理不使用它。
- 不改变日历布局、主题或组件架构，沿用共享加载与错误重试组件。服务端缓存内的原始记录从不直接返回匿名客户端，仍使用既有白名单投影。

## 验收与边界

本地验证：337 个 JavaScript 模块、94 份 Markdown 检查无错误，ESLint 无警告；Node 22/24 的 584 项 Node 测试通过，权限 26/26、账号 103 项、志愿资料 28 项通过。桌面/手机浏览器全量回归 224 项通过、38 项按设备范围跳过；发布安全 Python 测试 12 项通过，生产依赖审计无漏洞。

新增测试覆盖元数据合并、失败重试、禁用不联网、日历与目录共享快照且写入不使用快照，以及桌面/手机慢接口下首屏及时呈现、个人状态加载期间禁止提前加入、离页后的异步结果不覆盖下一页。运行现有报名、社区设计和完整项目回归。

本次只读探测生产接口，合成测试不连接真实 NJUTable、不创建报名或投递邮件。推送后的最终发布以 Actions 部署回执、服务器运行文件清单和公开页面核验为准；仅首次无缓存或上游失效时仍可能出现数据等待，不能承诺任意网络环境下固定完成时限。
