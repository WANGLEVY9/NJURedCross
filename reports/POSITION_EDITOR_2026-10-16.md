# 岗位配置工作区改造

## 变更与边界

- 分组报名活动在草稿、待审核阶段即可配置岗位。安排保存在原活动配置的 `positionDraft`，不提前生成公开报名岗位，不跳过审批。批准后可修改安排，也可直接统一发布并生成岗位。
- 已批准项目可调整未有报名的岗位，并新增岗位。已有报名记录的岗位保持原 ID、名单和邮件配置；改写、移除或重开已有报名记录的岗位会被拒绝。
- 修改已发布项目须确认暂停报名，服务端先关闭项目报名门禁，再更新安排；全部岗位生成完成后才允许统一发布。相同安排重复保存不关闭报名，中断可按原安排重试。
- `positionToken` 使用服务端当前配置摘要，防止过期页面覆盖新安排。权限验证和写入继续使用权威数据，未引入显示缓存决策。
- 普通岗位校区支持鼓楼、仙林、浦口、苏州；界面显示完整“校区”名称。存储使用既有 JSON 配置，不需要新增表、删除列或迁移真实业务记录。献血车自动排班流程不变。

## 界面

根因是抽屉挂载在 `.console` 之外，原 `.console .position-editor` 样式未匹配。使用独立命名空间，限制网格子项最小宽度，桌面双列、手机单列。

依照 frontend-design 技能，以岗位编辑为核心组织统一截止时间、名额汇总、编号岗位分区和固定保存区域；沿用现有主题与字体。截止、开始、结束三个时间均复用已有 `enhanceDateTimeField`，支持秒级、键盘、取消和焦点恢复。每个岗位可复制，复制后可继续复制或微调；重复岗位和总名额超限有校验。退出未保存输入有确认；保存成功但后续刷新失败会明确提示“岗位已保存”。

## 验证

- `npm run verify`：项目检查、ESLint、权限/身份检查通过；Node 测试 1934 项，1932 通过、2 项既有跳过、0 失败。
- `tests/project-positions.test.mjs` 覆盖审批前配置、发布门禁、浦口、草稿保留、范围冲突、已有报名保护、重新发布、重复岗位、中断重试。
- 浏览器覆盖桌面和移动 Chromium，以及 Firefox、WebKit。岗位测试包括复制、四校区、统一日历、320/390/1440px 越界检查、审批后发布、版本冲突、关闭保护和保存后刷新失败。
- Chromium 相关回归 36 项通过；Firefox/WebKit 岗位测试 4 项通过。并行测试曾因共用输出目录丢失 trace，改用独立目录后通过。
- 回归发现异步成员目录加载会重绘项目报名面板并还原未保存的截止时间；现保留同一项目的输入，并添加延迟目录响应的确定性测试。
- 合成数据仅写隔离预览服务，未向真实成员发送测试邮件，也未提交生产岗位安排。

浏览器图片输出到忽略目录 `.workflow-evidence/positions/{chromium-results,cross-results}/`。上线验收须另行核对 Actions、服务器发布清单与真实页面，以上测试不替代上线证明。
