# 物资恢复测试副本演练：2026-10-07

## 范围与环境

由贡献者在 Windows、Node.js 24 的本地仓库执行，连接已确认可写入及清理合成记录的独立物资测试 Base。
认证返回 UUID 与业务配置、显式演练目标一致。不记录 Token、Base UUID、账号 Cookie、真实身份资料或底表导出。

本次验证 SeaTable 写入、持久化恢复凭证和恢复模块；没有通过完整 HTTP/网页出库流程，不上传照片，不发送邮件，不验证跨服务器协调。

## 演练与结果

1. 只读检查：三张物资表存在，字段及状态选项满足演练要求，写入 0 次。
2. 创建带独立演练标识的模拟库存及申请；库存基线 3 件，借用数量 2 件。
3. 首次出库流水已写入，但日期返回格式导致恢复比较拒绝继续。只读诊断确认仅有 1 条流水，申请仍与操作前快照一致。
4. 修复明确日期字段的比较：日期字符串 `2026-10-07` 与 SeaTable 返回的 `2026-10-07T00:00:00+08:00` 视为同一日；不同日期、非午夜或不支持的时区仍不能通过该兼容规则，普通文本及数值仍严格比较。
5. 使用原标识执行 continue-fault；没有重新创建库存、申请或流水。流水核对通过后，在发送申请更新请求前注入异常；结果 passed=true、flowCount=1、退出码 0。
6. 启动新的 Node 进程执行 resume，从磁盘重新读取凭证，完成申请更新及模拟归还，并执行重复恢复检查。结果 passed=true、flowCount=2、returned=2、quantity=3、退出码 0。
7. 出库和归还各一条流水；按库存基线加流水增减计算，数量恢复为 3 件。
8. cleanup 校验记录 ID 和演练归属后删除本次两条流水、一条申请、一条库存；再次读取确认 remainingDrillRows=0、退出码 0。本地 manifest 和 SQLite 凭证保留。

## 故障含义与限制

注入故障发生在申请更新请求发送之前，验证的是“流水持久化成功、下一步未执行”的恢复路径。
它不等于网络断开后的未知写入结果，也不是在任意指令处强杀进程。
本次确实使用了不同 Node 进程恢复，但没有验收整站服务重启、真实 HTTP 客户端断开、上传照片及完整控制台交互。

同机共享锁和协调入口用于本次维护脚本；本次没有同时运行多个真实写入者进行容量压测。
跨服务器锁、其他仓库及第三方脚本协调、生产部署和备份恢复演练仍未验收。
