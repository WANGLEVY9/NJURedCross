# 活动中心④⑤：签到、时长审核与导出

张欣慰认领会议中的④签到核验与⑤时长审核/导出。本分支 `codex/attendance-hours-review` 从同步后的 `origin/main`（`c3fb8f4`）开始开发。按本次用户要求，不实现会后提到的动态签到码。

## 完成内容

- 签到表预填服务、培训、交通时长及工作内容，支持逐人调整、搜索、状态筛选、排序、选择当前结果及批量「确认签到并录入」。取消强制填写签到备注，献血车保留照片证据要求。
- 第⑤步显示与第二课堂导出一致的十列明细，独立审核、批量通过、填写原因退回，退回后可在第④步修改重提。核对摘要校验阻止过时的修改/审核；已批准明细不可直接编辑。
- 审核通过后自动下载真实 Excel，也可单独下载。只导出已批准/已入账记录，学号作为文本保留，时长为数值。HTTP 附件下载前用鉴权 HEAD 校验，兼容内置浏览器。
- 保留独立的个人时长同步，重复调用或半成功重试按绝对汇总重建，不重复加时长。沿用现有 `events` 权限及独立审批规则，`super_admin` 例外保持不变。本分支没有新增组织级主席/主任权限映射。
- 桌面可收起或显示活动列表；手机表格变为带字段标签的卡片，批量按钮置于表格上方。活动顶部四项统计保留。

## 真实测试库准备

已使用用户提供的测试凭证配置 Git 忽略的本地 `.env`，并只读认证、核对允许的测试 UUID 与 Schema。结果：只需给 `网站服务时长明细表` 增加 `工作内容`、`核对摘要`、`退回原因` 三个 text 列；其余流程表无需修改。

本轮没有执行云端增列、写入业务行或部署。`.env` 的试点写入开关仍关闭。真实服务在 Schema 未准备好时，会在任何流程写入前返回明确的 503，避免只保存签到却丢失核定时长。

维护者确认后，可先执行 `npm run workflow:schema:preview` 查看同一计划，再用 `node --env-file=.env scripts/apply-workflow-schema.mjs --apply` 仅增列，并启用测试开关。备份、兼容性及回滚说明见 [流程文档](../docs/WORKFLOW.md)。

## 验证结果

- `npm run verify`：模块/文档检查及 ESLint 通过；权限、身份、资料脚本通过；Node 行为测试 93/93 通过。
- `npm audit --omit=dev --audit-level=moderate`：0 vulnerabilities。ExcelJS 使用固定版本，并覆盖其有漏洞的传递 uuid 版本。
- 新回归覆盖批次部分失败、错误时长不创建签到、跨活动/重复选择、半成功重试、独立审批、退回修改、过时审核、已审不可改、真实 Excel 读取以及 GET/HEAD 的权限与附件响应。
- 实际浏览器完成：逐人时长调整 → 两人部分失败 → 修正后重试；退回并修改重提；批量审核后自动下载；手动重试下载；手机搜索、全选当前结果和提交。下载文件实际读取到十列、四条已审数据、数值时长。
- 390px 手机视口下页面和卡片没有横向溢出。桌面表格只在自身区域水平滚动。
- 同步后的原有 `public-read-cache` 源码截取测试依赖 LF 换行，在 Windows CRLF 下误截取到后续邮件初始化；测试读取时归一化换行后恢复，未修改该业务功能。

本机交互预览：`http://127.0.0.1:3121/console/workflow?event=synthetic-9&tab=checkins`；将 `tab` 改成 `hours` 可直达时长审核。它只监听回环地址，使用内存中的模拟志愿者；服务重启后重置，不访问真实 Base。本地截图见 `task6-attendance-desktop.jpg`、`task6-hours-desktop.jpg`、`task6-attendance-mobile.jpg`，图片不进入 Git。
