# 活动管理六环节改版（2026-10-17）

## 需求落点

按 10-17 的沟通记录：每个环节只给对应角色看对应页面与操作，固定三个按钮槽
（活动信息查看 / 活动信息修改 / 各环节操作），状态流转必须真的走得通。

## 状态模型

持久化状态扩展为 `草稿 → 待审核 → 可发布 → 报名中 → 进行中 → 已结束`
（`停点` 保留为献血车暂停态，`已归档` 保留回收站）。

- 新增 `进行中`：`POST /events/{id}/close` 从「直接结束」改为**报名截止**——
  关闭新报名，但现场签到、时长录入与导出继续可用。
- 新增 `POST /events/{id}/finish`：只有进行中/停点可以结束，写入 `已结束`。
  项目范围会同时关闭普通活动项目表的报名开关。
- 签到核验的允许集合加入 `进行中`；改写配置、调整负责人、恢复归档的状态白名单同步加入。
- 「时长审核」不新增持久化状态：时长记录本身就是提交动作。若把提交写进
  `报名页配置`，会抬高申请版本让已批准活动失效，因此由
  「进行中 + 存在 `待批准/已批准/已入账` 明细」派生。

判定集中在 `public/app/shared/activity-stage.js`（纯函数，6 项单元测试）。

## 页面与权限

| 环节 | 页面 | 操作槽 |
| --- | --- | --- |
| 待审核 | 活动预览 + 岗位预览 + 报名通知预览 | 审批通过 / 审批不通过（仅分管主席） |
| 待发布 | 只留报名通知预览，并提示改通知要走「活动信息修改」并重新审批 | 立即发布 / 定时发布 / 复制报名通知 |
| 报名中 | 报名名单表格，按岗位强制分块 | 报名截止 |
| 进行中 | 签到与时长录入 | 提交时长表 |
| 时长审核 | 时长审核工作区 | 在线预览 / 导出并发送 EXCEL（仅分管主席） |
| 已结束 | 只读摘要 | 查看时长表 |

- 固定槽第一位「活动信息查看」在任何状态都可打开（只读抽屉）。
- 「活动信息修改」只在草稿/待审核/待发布可用；岗位生成、来源班次、已发布活动置灰并给出原因。
- 环节导航只显示当前阶段真实存在的页，已结束不会再出现签到录入。
- 头部新增六段流程条，右侧给出下一步提示（状态栏原本空着的区域）。

## 名单与签到表

- 报名名单新增「岗位」列与岗位筛选；默认视图按岗位分块（分块表头显示
  「岗位一 · 引导岗 · 3 人」），行高 96px → 56px，操作按钮集中到行右侧。
- 签到表去掉「院系」「红会身份」两列，新增「岗位」列；两项信息移入
  「签到详情」抽屉。岗位数 ≥2 时表格上方显示编号对照说明。
- 岗位编号由 `public/app/shared/position-labels.js` 统一生成：按岗位配置顺序
  编号（岗位一…岗位一百），名单表、签到表、发布区共用。

## 未完成 / 已知边界

- **导出并发送 EXCEL 目前只下载文件**：`sendMail` 没有附件通道（邮件意图要
  做指纹与密封，加附件是独立改造）。导出抽屉里明确写了「自动邮件附件通道
  尚未开放，导出的文件需要人工发送」，不假装已发送。
- 多班次普通项目与献血车的报名页仍是卡片列表（`activity-center.js` 的 legacy
  分支），本次只改到表格版名单；与 A 类改动说明中的 A1 边界一致。
- 时长审核页允许负责人只读预览；批准与导出仅分管主席。
