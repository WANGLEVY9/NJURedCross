# P03：报名通知与报名成功邮件

2026-10-14。依据管理端审计文档 Prompt 03，在原生 JavaScript/CSS 工作区实施。基线为 `06524c9`。

## 视觉与操作

原发布区为单列长文本，概览另有编辑抽屉；保存、审批、发布的影响分散在不同入口。现在概览仅提供预览与前往编辑，发布页提供唯一的正文/北京时间设置、实时纯文本预览、当前状态及发布区。工作区窄于 720px 时改为单栏，手机控件保留触控高度。颜色复用管理端语义令牌，无新主题或运行依赖。

编辑状态会阻止审批及发布。恢复模板需确认；排期只同步约定的时间行，不清空自定义正文。失败保留输入；写入成功但刷新失败沿用明确的部分成功提示。刷新保留正在编辑的 DOM；检测到远端版本/状态变化时阻止继续保存，提示复制正文后重新核对。切换对象、页签、站内路由及浏览器返回支持放弃确认；保存请求进行中暂不允许站内离开；关闭/刷新浏览器使用原生未保存提示。

## 两类通知的边界

| 操作 | 业务影响 |
| --- | --- |
| 保存报名通知 | 原后端规则不变：回到草稿、批准失效、需重新提交审批 |
| 审批/发布 | 沿用服务端版本、权限、时间和状态校验；审批不会发名单邮件 |
| 保存成功邮件 | 新增可选能力；不发布报名公告、不变更批准、不发送邮件 |
| 最终确认名单 | 沿用原显式确认与邮件发送流程；自定义模板仅替换成功邮件 |
| 邮件重试 | 沿用原幂等键、持久发送记录及未知状态保护，不重复发送成功邮件 |

成功邮件编辑在普通筛选名单工作台内提供；直接录取的普通项目及源表自动献血车班次不强行套用此名单流程。自定义主题上限120字、正文5000字，允许姓名/活动名称/日期/时段/地点变量，拒绝未知变量与主题换行；正文为纯文本。默认关闭时继续原有简版邮件。第一次最终确认后冻结模板，包含之后重新调整名单的情况，避免失败重试产生不同内容；当前不提供后确认模板换版。

新增 `PATCH /api/volunteer/workflow/events/:id/success-mail` 沿用活动管理权限、CSRF、同源保护及写入串行化，使用名单 token 防止覆盖并发更新。数据存储于现有活动配置 `rosterReview.successMail`，无需新表/新列，不更换 NJUTable Token。公开活动 DTO 不返回此配置。
