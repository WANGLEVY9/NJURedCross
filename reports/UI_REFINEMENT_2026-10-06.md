# 活动入口与视觉检查（2026-10-06）

## 方向与实现

采用 frontend-design、impeccable 的布局与品质检查指导。保留红会品牌、已有主题与圆角模块，使用系统原生中英文字体；这一轮为现有设计的完善，不引入新的字体下载或动画框架。

| 检查项 | 原先问题 | 已实现 |
|---|---|---|
| 首页信息架构 | 前六条献血车班次占满近期活动；普通活动被挤出 | 读取完整公开目录后分类，献血车一个入口，普通活动独立展示 |
| 活动广场 | 每个周次仍有一个入口 | 所有周次汇总为一个献血车入口，保留地区与状态筛选 |
| 入口层级 | 班次、活动、个人记录混在同一页面 | 献血车入口进入专用日历；“我的报名”进入会员中心 |
| 视觉层级 | 渐变、阴影、嵌套卡片反复出现 | 收敛渐变、光斑与嵌套阴影，统计区合为一块，卡片与操作区按统一间距对齐 |
| 字体 | 超大标题与红色数字争夺注意力 | 原生字体明确标题/正文/辅助信息层级，数字使用等宽排版 |
| 交互语义 | 活动链接内嵌按钮 | 整张卡片保留一个链接，底部为非交互操作提示 |
| 动效 | 卡片光斑与重复入场效果 | 保留短促操作反馈、选中状态及箭头提示，尊重减弱动态效果设置 |
| 日历布局 | 标题区重复底部留白 | 清理额外间距；PC七列，手机周日期条与所选日班次 |
| 管理端共享组件 | 卡片中继续嵌套阴影统计、任务卡 | 移除嵌套提升感，以分隔线组织任务列表，维持既有导航 |

展示层聚合不会合并 NJUTable 行，也不会改变一行一个名额的规则。日历继续支持周切换、点位筛选、仅看有名额、班次详情、报名与既有请假签到功能。

首页目录与概览并行读取；活动入口不等待物资统计返回。没有新增业务表写入或邮件发送。

## 验证证据与范围

- `npm run verify`：项目检查、ESLint、权限/身份/个人资料测试与 109 项 Node 测试通过。
- 新增聚合测试覆盖 72 个跨周班次与普通活动共存、满额、空数据、缺日期等。
- impeccable 机械检测：本次修改目标无检测项；机械检测不替代人工视觉判断。
- CUA 本地只读预览使用生产公开接口快照：首页、活动广场均只有一个献血车入口，日历保留全部源班次。
- CUA 日历交互：PC七列；390px手机只显示选中日的班次；“下周”更新日期范围；点位筛选更新统计。
- 桌面1512px与手机390px检查：首页、活动广场、宣传广场、内建广场、物资广场、关于页无页面横向溢出；手机登录页无横向溢出。
- 管理端活动中心使用隔离合成环境检查PC与手机布局，无页面横向溢出；工作台、物资、志愿服务、宣传、内建、数据、设置页的合成/加载失败状态也检查了两种视口，没有页面横向溢出。这些状态不能证明真实数据表格与业务弹窗的验收结果。未以真实业务资料执行报名、审核或邮件发送。

本轮不是所有业务弹窗、所有账号状态的完整验收。会员登录后的资料表单、管理端各模块真实数据与全部主题组合仍需结合后续业务验收检查。
