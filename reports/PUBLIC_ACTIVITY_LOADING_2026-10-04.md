# 公开活动加载优化

## 原因

首页近期活动依赖公开总览接口。原实现先读取活动数据，再调用管理端志愿服务总览，分页读取报名总表、签到、审批、个人主页和时长汇总五张表；首页不展示这些结果。首页、活动列表与详情各次请求还会重新读取活动项目、场次和报名三张表。

## 修复

- 移除首页无关志愿服务读取；活动和库存查询并行执行。
- 在服务器内对公开活动投影和首页总览加入 10 秒缓存，合并并发请求。缓存不包含账号或参与者个人资料。
- 成功的 API 写操作使缓存失效；写操作仍执行原有实时读取和校验。外部直接修改表格时缓存会按期限刷新。
- 失败结果不写入缓存；写入前启动的查询不能重新填充失效缓存。
- 活动读表失败返回错误，避免把接口故障缓存为没有活动。
- 保留未使用的 volunteerRecords 响应字段为 null，保持响应结构兼容。

## 验证

同一本地客户端到现网 HTTPS 接口，单轮测量，不作为持续延迟保证：

| 接口 | 修复前 | 修复后 |
| --- | --- | --- |
| 首页总览 | 7.238 秒 | 首次 1.889 秒，重复 0.301 秒 |
| 活动列表 | 1.151 / 0.550 秒 | 0.296 / 0.673 秒 |

npm run verify 通过，共 221 项测试；新增四项覆盖缓存合并和过期、失败重试、写后失效及旧查询竞争、首页并发且无志愿服务依赖。公开路由 smoke 通过。浏览器确认首页近期活动展示正常。无业务数据写入。
