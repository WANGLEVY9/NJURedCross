# P04 · 名单、签到与时长工作流

2026-10-14。依据管理端审计 Prompt 04，基于真实原生页面实现；合成数据运行于隔离 preview，不写生产报名表。

## 审计与设计

| Before | After | Why |
| --- | --- | --- |
| 手机逐字段展开桌面表格，每人需滚动多屏 | 姓名、学号、状态、三类时长与一个核验入口；完整信息在 Inspector | 提高现场名单扫描效率 |
| 查看证据、关闭、编辑、关闭、勾选、提交 | 在同一面板查看到场依据、填写实际时长、明确确认后提交 | 减少单人操作往返 |
| 可见行自动请求签到详情 | 按需打开才请求，同一工作区复用在途/成功读取 | 避免列表产生逐人网络请求 |
| 签到/名单保存后重载全部活动目录 | 懒加载模式仅刷新当前项目详情 | 保留目录，减少无关请求 |
| 时长操作刷新整个页面并丢失批量失败选择 | 当前复核表刷新，保留失败明细 ID 和逐条原因 | 重试仅覆盖尚未成功记录 |
| 手机现场模式上方仍是大量概览和创建操作 | 精简现场页顶部；完整配置仍在非现场环节可用 | 缩短进入实际任务的滚动距离 |

桌面表格继续保持13px以上正文、可见滚动区域、姓名固定列、独立时长列与排序。手机控件触控高度44px，数字输入16px；排序收进展开项，选中记录后才显示批量主操作。沿用五套管理主题、现有共享按钮、勾选、Drawer、Modal 和 Toast。

## 工作流与状态

- 名单：保留现有暂定、最终确认与邮件送达三类状态和显式确认；增加姓名/学号排序、院系与来源；次级处理操作收进展开区。普通项目/献血车原有报名面板增加本地检索。
- 签到：原图、旧表记录、核验时间、核验人及备注继续来自原接口。图片失败提供明确提示和重试，不把缺少证据等同未到场。打开详情绝不会自动签到。
- 单人提交：需要明确勾选已核对到场情况，使用原 attendance-batch 接口。确认签到并录入实际时长只进入复核，不自动批准。
- 批量提交：保留200条上限，新增确认摘要；成功记录从本地选择移除，失败记录保留原因。签到成功而时长写入失败的情况提示核对最新记录，不宣称两步都失败。
- 时长：保留后端月度合并口径、单条明细身份、三类时长、摘要版本校验、他人复核与 Excel 导出门禁。合并行按明细修改，不向每次服务重复写入合计值。
- 编辑：签到输入和时长明细关闭时有未保存保护；现场页签切换保留取消后的输入；保存进行中阻止离开。成功写入后的刷新失败明确说明无需重复提交。
- 时长规则待定的普通项目仍只允许原有现场签到，不开放时长录入或导出。

未修改服务端业务规则、NJUTable 表结构、Token 或邮件发送逻辑。共享 `ui/table.js` 已审计，本轮保留其其他模块行为；定制业务表格与布局样式由对应活动模块和 `admin.css` 负责。
