# P01 / P04 / P05 桌面美术验收

## 审计与改动

旧背景由多个 CSS 文件重复控制：固定蓝色 Hero 与暖白正文割裂，experience.css 又持有独立 Hero 文字色；主题仅改变局部 accent。此次将五套色值集中到 themes.css，按路由控制光场；页面组件只消费主题变量。首页和内建展示标题使用自托管宋体，业务信息仍使用无衬线字。

实现约定见 [背景、主题与字体系统](../docs/ART_DIRECTION_SYSTEM.md)。本轮不添加轮播、不改 API 或生产表。

## 浏览器证据

- 五主题 × 首页/活动/周历/内建 × 1440×900、1920×1080，共 40 张完整页面截图；另检查 1280、2048 宽度。
- 合成数据仅运行在本地 workflow preview；截图中的模拟活动和统计不是生产数据。
- 主题文字/Canvas、Hero 文字/底色、按钮文字/主色、文字/Raised 四组基础对比度最低 5.78:1。此数字不宣称覆盖每一个半透明叠加像素。
- 日历筛选上下文、主题偏好隔离、减少动态、forced-colors、桌面/手机宽度继续回归。
- 字体阻断时仍可阅读和操作；最初发现提前显示页脚导致布局位移，现通过主内容最小高度预留修复。
- 同一 Chromium、1440×900、同一合成首页的单次本地观测：改前 CLS 0，正常字体加载约 0.000023，延迟字体 1 秒约 0.000059，字体完全阻断 0。此为实验室快照，非真实用户 Core Web Vitals。

原始截图、contrast.json、font-loading.json 在本轮交付的截图目录。全量测试和部署结果另以最终任务回执为准。
