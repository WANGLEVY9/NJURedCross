# 邮件发送与恢复

邮件通过 lib/mailer.js 统一发送。SMTP 发送状态保存于写入状态目录的
mail-deliveries.sqlite；安全通知重试队列保存于 mail-retries.sqlite。

## 去重与记录恢复

- 同一幂等键绑定收件人、主题、正文和邮件类型，
  内容不同的重复请求会被拒绝。
- 历史发送记录按页读取。读取失败或达到完整读取上限时，
  不将结果当作“未发送”，不启动 SMTP 发送。
- 已确认发送的邮件不会因为发送记录保存失败而重新发送。
- 后台每分钟尝试补写发送记录，每轮最多处理 5 条。
- 已进入发送阶段但结果不确定的任务停止自动重发，
  需要维护者核对邮件服务记录后处理。
- 本地发送状态在进程重启后保留。

## 安全通知重试队列

密码修改、密码重置后的 security 类型通知接入持久化队列。
SMTP 配置完整时，初次发送前先保存加密内容和任务有效期。

- 通知有效期为 24 小时，重复请求不会延长有效期。
- 初次发送前失败后，后台最多尝试投递 4 次，
  等待间隔依次为 1 分钟、5 分钟、15 分钟和 1 小时。
- 每次后台尝试前保存尝试次数；中途退出不会将次数重置。
- 只有发送状态允许安全继续时才会再次投递；
  sending、unknown 等状态不会自动重新发送。
- 到期、达到次数上限、正文无法解密或内容校验失败的任务停止处理。
- 验证码和逾期提醒不进入自动投递队列。
- 后台每轮最多处理 5 条投递任务，
  与记录修复共同使用请求超时限制和同机共享写入锁。
- SMTP 未配置时，后台投递入口直接返回。

物资逾期提醒仍使用统一发送入口；
未确认发送成功时不写入“邮件已发送”的物资流水。

## 数据保护与备份

发送状态库保存收件人、主题、类型、内容指纹和发送状态，
不保存明文正文。重试队列另外保存加密正文。

正文使用 AES-256-GCM 加密，并绑定任务键及内容指纹。
加密密钥由会话密钥派生，密钥不写入数据库。

收件人、主题和加密正文仍属于需保护的数据。
状态目录应使用受保护的本地磁盘，并纳入备份。
运行中的 SQLite 数据库应使用 SQLite 支持的一致性备份方式，
不能仅复制主数据库文件并忽略 WAL。

更换会话密钥可能导致旧任务无法解密或内容核验失败。
不能通过删除数据库来强制重发。

## 当前边界

- 仅支持参与同机写入协调的进程，不保证跨服务器协调。
- 不保证邮件恰好投递一次；SMTP 结果不确定时要求人工核对。
- 尚未提供停止任务的人工处理界面或自动数据保留清理。
- 队列尚未覆盖所有邮件类型。
- 旧 SeaTable 发送记录没有正文指纹，
  只能核对其现有收件人、主题、类型和通道字段。
- 开发控制台输出不代表真实投递。
- 当前验证使用合成数据和模拟 SMTP，
  未完成真实 SMTP 故障及投递验收。

## 只读任务诊断

在仓库根目录运行：

```powershell
node --env-file=.env scripts/inspect-mail-state.mjs
```

工具读取 PLATFORM_WRITE_STATE_DIR 指定的状态目录；
开发环境未指定时使用仓库的 .write-state。
生产环境必须明确指定状态目录。
输出只包含发送状态数量、待补写记录数量及队列状态数量，
不输出邮箱、主题、正文、密钥或内容指纹。
工具不会发送邮件或修改任务状态。
数据库缺失或读取失败时返回非零退出码，
不会创建缺失数据库，也不会将失败报告为空任务。
两个数据库分别读取，不构成跨数据库原子快照。
服务运行时任务数量可能继续变化。
sending 或 unknown 状态需要结合 SMTP 服务记录人工核对；
stopped 表示自动投递已停止，不等于确认邮件未送达。
本工具不提供强制重发或修改状态功能。

### 按记录编号查询具体任务

使用本地 SMTP 发送状态生成的 MAIL-UUID 记录编号查询：

```powershell
node --env-file=.env scripts/inspect-mail-state.mjs --record-id=MAIL-00000000-0000-0000-0000-000000000000
```

示例编号用于验证“记录不存在”的情况；实际使用时替换为目标记录编号。

查询结果包括发送状态、远程留痕确认状态、创建和更新时间，
以及关联队列的状态、尝试次数、到期时间和下次尝试时间。
队列时间为 Unix 毫秒时间戳。

输出不包含邮箱、主题、正文、内容指纹或内部任务键。
没有对应记录时返回 found: false；
没有关联重试队列时 retry 为 null。

该命令只查询本地状态，不会核实 SMTP 服务是否实际接受或投递邮件。
sending、unknown 和 stopped 等状态仍需维护者结合外部记录核对。
工具不支持 --apply、强制重发或修改任务状态。


### 列出需要检查的任务编号

```powershell
node --env-file=.env scripts/inspect-mail-state.mjs --attention --limit=20
```

列表包含 pending、sending、unknown，以及尚未确认远程留痕的 sent 任务。
pending 可能只是正常等待处理，不代表发送故障。

每页默认 20 条，允许 1～100 条。输出不包含邮箱、主题或正文。
使用列表中的 recordId，可以继续按编号查询具体任务。

hasMore 为 true 时，将 nextCursor 填入下一页命令：

```powershell
node --env-file=.env scripts/inspect-mail-state.mjs --attention --limit=20 --after=MAIL-00000000-0000-0000-0000-000000000000
```

示例游标需要替换为实际 nextCursor。hasMore 为 false 表示本次查询没有后续页。

列表按记录编号排序，不按创建时间排序。
各页独立读取，运行中的任务状态和数据可能变化，
分页结果不构成跨页冻结快照。不得仅凭此列表决定强制重发。
