# 邮件发送与记录恢复

邮件通过 lib/mailer.js 统一发送。SMTP 发送使用本地 SQLite
持久化发送状态，数据库位于写入状态目录的 mail-deliveries.sqlite。

## 重复请求与失败处理

- 同一幂等键绑定收件人、主题、正文和邮件类型；内容不同的重复请求会被拒绝。
- 历史发送记录按页读取。读取失败或达到完整读取上限时，
  不将结果当作“未发送”，不启动 SMTP 发送。
- 已确认发送的邮件不会因为发送记录保存失败而重新发送。
- 后台每分钟尝试补写发送记录，每次最多处理 5 条，
  使用请求超时限制和同机共享写入锁。
- 已进入发送阶段但结果不确定的任务停止自动重发，
  需要维护者核对邮件服务记录后处理。
- 本地发送状态在进程重启后保留。
- 物资逾期提醒已接入统一发送入口；
  未确认发送成功时不写入“邮件已发送”的物资流水。

## 数据与运行要求

本地数据库保存发送状态、收件人、主题、邮件类型及内容指纹，
不保存邮件正文或指纹密钥。上述元数据仍需受保护。

内容指纹使用会话密钥生成。密钥更换后，旧任务的内容核验可能失败，
不能通过删除数据库来强制重发。

状态目录应使用受保护的本地磁盘，并纳入备份。
运行中的 SQLite 数据库应使用 SQLite 支持的一致性备份方式，
不能仅复制主数据库文件并忽略 WAL。

## 当前边界

此机制不保证跨服务器协调，也不能保证邮件恰好投递一次。

后台任务补写的是已发送邮件的记录，不是通用邮件投递队列。
发送前失败的请求可由调用方再次提交；
尚未实现所有邮件任务的自动投递重试、退避和人工核对界面。

旧 SeaTable 发送记录不包含正文指纹，
只能核对其现有收件人、主题、类型和通道字段。

开发控制台输出不代表真实邮件投递。
