# Web 端视觉与交互实施计划

## 目标与边界

面向使用电脑查找班次、比较地点并完成预约的师生，深化现有红会品牌和原生 JavaScript/CSS 组件。优先完善献血车日历、组合筛选、班次详情与共享导航；保留手机版布局、五种主题和业务状态语义。实现不得改变报名资格、名额计算、权限或后台接口。

## 可复用设计 Prompt

### 艺术指导

以南京大学红十字会的真实标识和服务内容为基础，设计具有艺术表现力的桌面预约工作区。将珍珠白表面、深红操作重点、冷灰文字和方向性光场组织成有层次的画面。大屏以周日程作为视觉主体，月份与筛选工具形成清晰的控制区；通过字体比例、留白和表面明暗塑造质感。保留绿色可报名、炭灰满额、黄色待审核、蓝色报名成功的独立业务含义。采用系统中文字体栈，避免外部字体加载影响使用。

### 组件与交互

把日历作为连续的工作界面设计。提供舒展和紧凑两种桌面密度，使用户能够比较少量或密集班次。日期支持方向键与 Home/End 导航，焦点与选中态清晰。筛选结果准确反映实际显示内容；选择班次后可明确返回原日历位置。所有操作即时响应，鼠标切换可以有短暂空间过渡，键盘操作与减少动态效果模式保持直接。按钮、分段筛选、日期与卡片均应覆盖悬停、按下、焦点和选中状态。

### 验收与实现约束

保留原生组件、路由、真实文案和业务接口。以 1280、1440、1920px 桌面尺寸检查构图、密集班次与空结果，并回归 390px/320px 手机布局。检查键盘、组合筛选、返回日历、主题和减少动态效果。测试使用合成数据；线上仅执行读取与展示交互，不提交真实报名。

## 设计决策

| Before | After | Why |
| --- | --- | --- |
| 日期、卡片和控制区的尺度接近 | 桌面月份与周范围形成明确锚点，日期与卡片分层 | 加快大屏扫描 |
| 密集班次只能长距离滚动 | 桌面提供舒展/紧凑密度切换 | 用户可依据数据量调整阅读密度 |
| 查看详情后需要自行滚回日历 | 详情前提供“返回日历”并恢复原班次焦点 | 保持选择上下文 |
| 日期主要依赖点击 | 方向键、Home/End 移动日期并保持焦点 | 提升键盘效率 |

配色沿用 `DESIGN.md`：深红 #b91c37、底色 #f5f4f8、白色 #ffffff、正文 #30313d、次要文字 #646574、可报名浅绿 #f0f6f4。主题操作色仍由既有 CSS 变量决定。

## 执行顺序

1. 对照当前实现与线上截图，确定桌面断点和组件边界。
2. 调整日历控制区、日期/卡片比例、表面光影和桌面导航反馈。
3. 实现密度切换、日期键盘导航与详情返回焦点。
4. 批量检查桌面和手机截图，修复确证问题，执行项目与浏览器回归。
5. 同步设计文档，提交 main，核验 CI、服务器发布回执、线上资源和页面。
