# 工作助手使用与维护

## 当前能力

工作助手支持活动筹备、推文创作和美编建议。

新任务采用持续对话。首次发送需求后，助手展示需求理解，
并集中提供可以补充或修正的草稿字段。未知信息允许留空。

点击一次“确认并生成”后，直接生成完整方案。
之后在同一个输入框发送修改意见，不重复确认各个工作步骤。

生成前按当前账号权限读取相关活动、物资和宣传记录。
结果展示来源和读取时间；读取失败或覆盖不完整时明确提示。
当前采用有限关键词匹配，不是完整的语义搜索。

系统参考记录不等于本次活动事实，也不代表物资已经预留。
真实模型模式下，相关记录摘要会随需求发送到模型服务。

完整结果中的草稿字段可直接带入折叠的编辑器。
用户可以展开编辑、预览并保存。
保存草稿不会清空尚未发送的对话输入。

生成新的修改结果后，需要重新核对并保存草稿，
再进行活动表单交接或复制已保存正文。
生成或保存失败时保留原有任务与编辑内容。

已保存的活动配置可以带入新建活动表单，但不会自动创建活动。
用户仍需核对负责人和其他字段，并按活动管理流程提交。

历史列表支持恢复和删除任务。
旧版分步任务继续使用原有界面，不自动迁移为对话任务。

模拟模式只演示交互，不自动提取事实或理解语义修改。
真实语义生成与修改由接入的模型完成。

推文与美编方案不会自动发布到外部渠道。
美编预览使用固定配色和版式，不执行模型生成的 HTML 或 CSS。


## 模拟模式

默认使用模拟模型，不需要 API Key，也不会调用真实模型。

模拟结果用于验证流程，不能作为真实活动事实或正式宣传内容。

环境配置：

    AGENT_MODEL_PROVIDER=mock

## 接入 DeepSeek

真实模型配置仅放在服务器环境变量或本地 .env 中。
不要把真实 Key 写入前端、测试、日志或提交到 Git。

需要配置：

    AGENT_MODEL_PROVIDER=deepseek
    DEEPSEEK_API_KEY=填写真实Key
    DEEPSEEK_MODEL=填写账号可用的模型名称
    AGENT_MODEL_TIMEOUT_MS=60000
    AGENT_MODEL_MAX_TOKENS=3000

修改配置后重启服务，并在工作助手页面确认当前模型状态。

先使用不含个人信息的合成需求验证连接与输出，再处理实际业务。
真实调用可能产生费用，模型名称与可用权限以服务商信息为准。

接口出现错误时，不自动重试，也不自动切回模拟模式。
调用失败不会覆盖原有任务结果或草稿。

## 调用次数与并发

默认配置：

    AGENT_CALL_MAXIMUM=20
    AGENT_CALL_WINDOW_MS=3600000
    AGENT_ACCOUNT_CONCURRENT=1
    AGENT_GLOBAL_CONCURRENT=4

每个账号从首次获准调用起，在一个小时内最多调用 20 次。
同一账号最多同时调用一次，整个服务最多同时调用四次。

生成方案和修改草稿建议共用额度。
已经获准发起的调用即计入次数，包括后续失败的调用。
在调用前被额度或并发限制拒绝的请求不计入次数。

调用次数不是精确的费用上限。实际费用还取决于模型、
输入长度、输出长度和服务商计费规则。

限制状态保存在进程内存中，服务重启后重置。
多个服务进程之间不共享额度。
多实例部署前应改用共享存储协调额度和并发状态。

## 任务存储与删除

任务保存在 `PLATFORM_WRITE_STATE_DIR` 指定的服务器私有持久目录中：

    <PLATFORM_WRITE_STATE_DIR>/agent-tasks.json

非生产环境未配置时才使用仓库内的 `.write-state`；生产环境必须显式配置私有目录。

任务列表按当前账号和模块权限过滤。
用户不能通过替换任务地址读取其他账号的任务。

本地文件可能包含需求、草稿和内部核对内容，
应限制访问并按实际需求进行备份。

保存采用临时文件写入后替换目标文件。
当前方案面向单进程使用，不适合多个进程共同修改同一文件。

删除历史任务需要确认。当前没有回收站；
删除后只能从已有备份恢复。

不要把任务存储文件、临时文件或真实业务数据提交到 Git。

## 人工核对

字段格式完整不代表事实已经核实。

活动配置需要核对时间、地点、容量、岗位、物资和负责人。
推文需要核对日期、人数、引用、活动结果和图片授权。
美编需要核对可读性、对比度、素材授权和隐私信息。

未知事实应留空或标记待确认，不能因为模型提供了答案就直接采用。
正式创建活动、业务审批和外部发布仍按原有流程执行。

## 离线验收

执行：

    node scripts/evaluate-console-agent.mjs

运行器固定使用模拟模型，即使环境中配置了真实 Key，
也不会因此调用真实模型。

九个合成案例覆盖三种工作模式，各包含：
完整需求、缺失信息、指定字段修改。

报告中的 structuralPass 只表示输出结构通过检查。
draftComplete 只表示草稿满足字段校验。
两者都不代表内容真实、质量合格或可以直接发布。

报告同时列出需要人工检查的事项。
接入真实模型后的内容质量验收仍需另外进行。

## 常见问题

模型状态无法读取：
检查登录状态、服务器运行情况和接口错误提示，
恢复状态后再生成。

达到调用上限：
等待当前额度窗口结束，不要连续重复提交。

账号或服务繁忙：
等待正在进行的调用结束后重试。

生成超时或失败：
保留原有输入，检查服务器配置与服务商状态，
确认恢复后由用户重新发起调用。

保存失败：
保留当前编辑内容，检查服务器存储权限和磁盘空间，
不要直接关闭页面。

历史任务无法读取：
检查账号权限及任务文件是否完整。
文件损坏时应先保留原文件，再从备份恢复，
不要用空文件覆盖原有任务。
