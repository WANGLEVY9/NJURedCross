# 管理端活动工作区第二版

## main 集成状态（2026-10-18）

- `/console/events` 与 `/console/workflow` 统一加载六阶段活动工作区；`legacy=1` 不再切换界面。缺少服务依赖时显示错误，不回退旧版。
- 已移除“旧版活动”入口。旧记录保留存储，但不在新目录中伪造迁移状态。
- 地区审批使用私有名单文件 `PLATFORM_ACTIVITY_WORKSPACE_ROSTER_FILE`。名单只提供账号、地区、角色和中心类别；账号启用状态、邮箱验证和邮件地址每次从当前身份库读取。文件缺失、无效或账号无法验证时失败关闭，不按姓名、校区或同名组织推断。
- 旧版指定审核人、整表时长提交/退回、签到证据、独立结束和献血车流程继续沿用原规则。只有带 `workspaceSubmission` 或 `workspace-regional` 证据的新版活动走地区主席团审批。

## 当前范围更正（以此处为准，2026-10-18）

完整确认需求见 [活动管理重建需求](ACTIVITY_WORKSPACE_V2_REQUIREMENTS.md)。最新界面修订：不显示创建人、清除筛选和局部刷新；批量模式才显示勾选框与批量结果动作；单岗位隐藏岗位切换；主任初审下拉判定，签到链接/照片为可选资料。下文旧记录中的强制签到附件要求已取消，但仍须完成主任初审、填写不通过原因和完整预览后提交；不自动创建签到。通知按招募文案组织，多岗位安排合并到工作内容下逐岗列出。

- 本次重建只展示新草稿和新流程项目，不物理清理业务数据；历史组件通过测试专用注入保留回归覆盖。
- 选择活动后，六阶段操作均在右侧操作盘面完成，允许既定的预览/确认浮层，不跳往第二个活动管理页面。左侧卡片与右侧内容独立滚动，标题、进度和工具栏固定。
- 下文分批开发记录中的“开发入口、旧活动兼容、以后迁移、岗位下拉筛选”等历史描述不再作为当前需求；岗位强切换、地区审批及用户后续修订优先。真实名单与生产适配仍未接入，不代表已经上线。
- 独立预览启动器只展示新流程，准备草稿、待审批、报名中、进行中、时长审核和已结束六阶段合成样例。统一工具栏、字段标签、控件内边距与卡片圆角，活动说明占满可用行宽。

此分支以 main d7accf8 为基线，按确认过的草稿页范例分批实现。所有正式管理页面继续使用现有 console shell、会话与原生 JavaScript 组件，不将独立预览中的模拟账号、本机存储和状态切换带入业务页面。

## 已实现的基础模块

- `public/app/shared/activity-workspace.js`：六阶段展示、地区类别强绑定、草稿字段白名单、多日活动和分钟级岗位时间校验、通知生成、基于权威账号名单的权限判定。
- `lib/events/workspace-drafts.js`：可保存不完整信息的草稿服务，注入持久化与权限依赖，创建请求幂等、保存版本冲突、只读预览、显式确认预览。提交函数仅产生已验证计划，不修改活动状态。
- `public/app/console/pages/activity-draft-workspace.js`：正式页面内编辑组件。通过宿主提供的真实接口保存、预览和提交，不含模拟服务；使用共享表单、选择器、抽屉与错误提示。
- `public/styles/activity-workspace.css`：圆角卡片、操作区、表单及岗位表格样式。公共导航通过 admin.css 的 `--nav-w` 引用统一的 200px 变量，各管理页面一致；活动目录为 250px。

## 仍需接入

已增加开发入口 `/console/events?workspace=v2`，复用真实 console shell。草稿存储、名单、草稿转换和地区审批已接入服务模块；正式环境仍须配置功能开关、可信名单与存储依赖，缺少依赖时不会开放提交。

生产服务默认不开启新草稿 API；只有设置 `PLATFORM_ACTIVITY_WORKSPACE_V2=true` 才开放开发入口所需的草稿服务。合成预览脚本始终提供隔离的内存草稿服务，不读取生产配置、不写真实 NJUTable。

真实服务将草稿存入 `PLATFORM_WRITE_STATE_DIR/activity-workspace-<数据源摘要>.sqlite`。该文件包含内部活动内容，不能放入静态资源目录、源码或公开备份；备份、恢复和发布保留规则与该私有目录一致。SQLite WAL 模式应使用一致性备份或停止服务后备份，不能在写入中仅复制主文件。

草稿 API 根据当前可信名单授予所属地区主席团、所选分管主任访问与提交前编辑权限；移交后创建人仅可查看。跨地区和已撤销权限拒绝访问。选择类别仍通过现有类别创建权限校验；草稿权限不替代正式审批和发布权限。

持久化已使用私有 SQLite 与统一草稿队列。存储更新通过事务及版本条件检查拒绝独立连接的旧版本写入；同一作者的创建标识有唯一约束，重试不会另建草稿。不能在页面组件中使用 localStorage 替代正式草稿持久化。

提交计划的应用必须在同一权威写入边界内重新核对当前版本、最新预览摘要、账号名单与地区权限；不能先读取计划、等待其他操作后直接照旧应用。

## 提交交接记录

`workspace-submissions.js` 已实现可持久恢复的交接协调器，正式业务写入之前先用 SQLite 版本条件写入提交记录，冻结草稿，分配稳定活动 ID 和唯一交接标识。两个独立数据库连接同时提交时，仅获得版本写入权的一方可调用业务创建。

业务成功凭据必须同时匹配活动 ID、交接标识与预览摘要。响应丢失后，重试只调用权威只读核对，不再调用创建；未查到或凭据不匹配时保持“结果待核对”，禁止继续修改。即使是写入前断线也不自动重建，需要后续管理核对途径处理，避免把“暂未查到”误当成“从未写入”。完成交接后进入待审批，仍能查看保存内容。

接口仅在服务端明确提供 `getWorkspaceSubmissions` 时开放 `POST /workspace-drafts/:id/submit`；默认服务和当前开发预览均未注入，页面提交按钮仍关闭。协调器的 `prepare` 必须解析可信负责人并核对地区名单，`apply` 必须在正式工作流写入边界重新核对权限与交接记录，`inspect` 必须读取权威业务记录而非展示缓存。当前测试以隔离业务适配器验证协议，尚未表示真实 NJUTable 活动创建已接通。

## 账号与地区

南京与苏州的主席团、中心主任组织名称一致，不通过名称是否包含“苏州”判断地区。使用账号名单的地区、角色、中心证据绑定，客户端传入的身份不能作为授权。

当前缺少已验证名单时，`workspacePermissions` 返回拒绝。只允许本地区主席团处理对应活动审核，本地区本项目负责人编辑草稿；其他中心或地区主任不得因此获得编辑权限。

名单提供者需要返回当前有效的 `actor`、`verified`、`active`、`region`、`role`、`categories`。这些值只能由服务端从可信名单构建，不能直接接受表单字段。

负责人候选仅为活动所属地区、分管中心的有效主任，主席团具有选择管理权限但不自动列为负责人。表单保存 `responsibleId` 作为候选账号选择，不能把该字段当成浏览器授予的角色或访问权限；实际创建人身份仍由服务端记录。选择或更换负责人参与完整预览摘要，保存后旧预览确认失效。实际权限移交和正式工作流负责人绑定仍待转换接入，不能仅凭保存一个负责人 ID 就宣称已完成授权移交。

`workspace-responsible.js` 校验负责人名单，并通过既有“账号关联表”的 `账号ID / 资料BaseUUID / 资料行ID / 资料同步状态` 只读解析个人档案，核对有效账号、唯一关联及学号姓名一致性，不复制或创建档案。接口只返回姓名、院系、年级、校区，不泄露电话、邮箱或真实资料行标识。同名主任以账号 ID 区分，不按姓名选人或猜测关联。

开发页面已接入主任选择、按地区类别重载和档案查看抽屉。名单读取失败不清空其他输入；切换地区或类别会清空原负责人。保存负责人时由 `validateResponsible` 重新读取当前名单，名单缺失、停用、跨地区中心或主席团候选均拒绝。默认真实服务未配置名单验证器，不能保存非空负责人；目前只有隔离预览明确提供合成名单与合成档案。后续应将 `getWorkspaceRoster`、`getWorkspaceProfileData` 和保存验证器同时接到可信数据源，不能读取全部真实档案后不经权限过滤直接返回。

`workspace-roster.js` 提供可信名单适配边界：以稳定账号 ID 与活动所属地区共同查找，完整名单中必须唯一命中且仍有效。主任团还需匹配中心及活动负责人；主席团仅获得本地区权限。相同组织名称、全局管理员标签、缺失或重复名单均不能代替地区证据。此适配器尚未接入实际名单来源，不能因此宣称已开放地区审批。

`workspace-approval-routing.js` 已实现可注入现有工作流的地区审批适配器，按完整可信名单分配本地区主席团，绑定地区、类别与申请版本；实际审核时重新读取名单。新增成员不会自动接管旧申请，停用或撤销即时拒绝审核，不回退到旧的全局超管规则。测试已接入真实 `createWorkflow` 验证退回、重提、审批通过后等待发布；生产与开发入口尚未切换到该适配器，仍等待实际名单和草稿转换边界。

### 审批通过与发布（更新总需求）

发布不再授权项目负责人，统一由活动所属地区主席团处理。南京与苏州分别绑定当前有效主席团，立即发布、设置/调整定时和撤销定时均重新检查权限，不能只隐藏前端按钮。HTTP 接口从会话传入操作者，不使用请求正文中的角色或账号覆盖。

地区审批成功后打开“审批通过 · 发布活动”弹窗，发布方式下拉选择立即或定时。定时时间不预填，必须主动选择未来北京时间，实际提交仍由服务端验证早于活动/岗位开始和报名截止等边界。取消或关闭弹窗保留审批成功的待发布状态，后续仍由本地区主席团完成发布；已批准活动可再次打开发布选择，不重新审批。发布结果不明确时停止重复操作并提示刷新核对。

此流程挂接在 `approval.mode=workspace-regional` 的新地区审批活动中。工作流通过地区适配器的 `assertPublisher` 执行写入前检查，缺少地区发布服务时不回退到旧全局权限。旧审批策略尚未迁移的活动沿用原策略和界面，不能据此宣称所有旧活动或生产权限已切换。浏览器测试覆盖真实弹窗组件的立即/定时、时间留空、过去时间拒绝和稍后发布；真实工作流测试另行覆盖负责人及跨地区拒绝、主席团定时/撤销及停用即时拒绝。

类别与既有共享分类常量一致，新增完整名称“排班类”；南京七类、苏州五类。合成预览的审核账号夹具同步包含排班类，不对应真实人员。

## 草稿版本

界面统一使用“岗位数量”下拉框，选项严格为“待选择 / 单岗位 / 多岗位”。初始值为空，仅显示“待选择”，必须主动选择后才展开活动安排、岗位配置和通知等后续内容。为兼容已有活动与复制数据，内部继续使用 `bookingMode` 的空值、`unified`、`grouped`，不修改既有数据含义。预览、切换确认和校验提示使用同一新表述；通知正文中的“报名方式”仍表示实际报名途径，不是岗位数量选项。

### 复制为新活动（补充总需求）

- 复制结果一律进入草稿，生成独立活动 ID，并在侧边活动目录增加和选中新卡片。
- 复制基本信息、报名方式及**完整岗位配置**：每个岗位的名称、日期、具体开始结束时间、校区、地点、人数、工作内容、服务/培训/交通时长均保留。所有岗位生成独立新 ID，不与原活动共用业务关联。
- 不继承审批通过状态、预览确认、报名、签到、时长或提交交接状态，原活动保持不变。
- 按新活动信息和完整岗位安排生成通知。自动通知会随基本信息、日期时段和岗位编辑同步更新，保存端也校正自动通知；用户主动手工编写的正文不无提示覆盖。
- 同一复制请求重试返回同一个草稿及岗位，不重复创建；复制前校验来源版本及读取、创建权限。

当前实现已接入新草稿工作区的“更多操作 → 复制为新活动”及草稿复制 API。新工作区也已为旧网站流程活动提供复制入口，源数据通过当前请求的正式活动权限证据读取；目录携带申请版本，写入新草稿前校验。转换读取完整 `positionDraft / positionPlan`，待审批岗位草案与已发布岗位计划均覆盖，原活动及其报名、签到、时长数据不变。合成浏览器验证通过实际旧创建、岗位保存 API 后再操作新复制入口，不用简化假岗位替代。

旧负责人仅在仍可验证为对应地区中心的有效主任时保留；名单未接入或不再符合条件时，新草稿留空待重新选择。配置损坏、缺失完整岗位、跨日单岗位或秒级时间等不能在新编辑器中无损表达的数据，明确拒绝，不悄悄截断时间或只复制活动父行。旧式独立班次记录需选择完整项目，不能把其中一个班次误复制为整个项目；此类整组迁移仍待接入。原工作区本身未切换，新草稿仍保持私有草稿，真实提交审批和名单接入尚未开放。

保存允许空报名方式、空日期与空时长，不设置默认值或编造事实。提交才验证完整信息。岗位 ID 与活动 ID 稳定，复制岗位产生新 ID。

生成预览不等于用户已阅读。显式确认绑定操作者、草稿 ID、版本与完整内容摘要。任何保存递增版本并清空预览确认，提交计划不得跳过该检查。

服务不修改既有活动审批摘要、不产生报名行、不发布、不发送邮件。后续接入必须保留旧活动 ID、报名、签到、时长关联，以及原有不确定结果核对机制。

现有分岗位生成服务已支持每个岗位可选的 `serviceHours`、`trainingHours`、`travelHours`，省略时保留原有继承逻辑；明确设置时写入对应子活动及批准摘要。岗位时长进入岗位定义摘要，重试沿用原 ID，已有报名的岗位不能通过更换时长偷偷改写。新工作区转换尚未接通，不能把这项兼容修正视为已开放提交。

### 报名规则补充（2026-10-18）

- 本项目负责人（名单中仍有效的对应地区、中心主任）与本地区主席团均可直接截止，无需二次主席团审批；其他主任、跨地区主席团不可操作。
- 截止前须检查整个操作范围及关联源活动的所有有效报名，全部已成功或失败且无待审请假，方可进入进行中。零报名不阻止截止。
- 新地区策略下成功、失败均立即落盘并进入既有可靠邮件发送队列，客户端不能用 immediate:false 绕过。失败原因必填，默认“很遗憾的通知您，您报名的活动已满”，可编辑。
- 不再提供一次性的报名结果通知操作；失败发送仍需保留可靠重试与回执核对能力。
- 人数达到容量时阻止新增报名，仍停留报名中；“报名已满”展示、进行中回退报名中的页面与完整约束尚待接入，不代表本批已完成。
- 上述变更仅适用于 workspace-regional 策略，旧活动迁移前保留原流程。


### 报名回退与满额子状态（2026-10-18）

- 名单工作区显示“报名中 · 报名已满”，以待筛选、已确认、已签到和源表占用合计判断，不改变主阶段。拒绝或请假释放名额后恢复接受报名。
- 新地区策略的进行中活动新增“返回报名中”；本项目主任、本地区主席团可操作，原因必填并写入操作审计。
- 回退保留报名结果及邮件回执，不重发既有通知；必须尚未开始、无签到/时长记录、审批仍有效，项目内各岗位均通过检查。项目原截止时间已过不能回退。
- 项目共享报名开关最后开放，避免岗位更新中途接受报名。网络中断后的多岗位状态恢复及修改过期截止时间另行补充。

- 验证覆盖模板工作簿往返读取、整数培训时长、文本学号、跨地区权限、身份覆盖拒绝、编辑同步、过期导出、失联响应重试、冻结文件一致性及邮件附件幂等；浏览器覆盖负责人只读、主席团修改与完整预览、导出到已结束、负责人下载。
