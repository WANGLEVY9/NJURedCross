# 管理端活动工作区第二版

此分支以 main d7accf8 为基线，按确认过的草稿页范例分批实现。所有正式管理页面继续使用现有 console shell、会话与原生 JavaScript 组件，不将独立预览中的模拟账号、本机存储和状态切换带入业务页面。

## 已实现的基础模块

- `public/app/shared/activity-workspace.js`：六阶段展示、地区类别强绑定、草稿字段白名单、多日活动和分钟级岗位时间校验、通知生成、基于权威账号名单的权限判定。
- `lib/events/workspace-drafts.js`：可保存不完整信息的草稿服务，注入持久化与权限依赖，创建请求幂等、保存版本冲突、只读预览、显式确认预览。提交函数仅产生已验证计划，不修改活动状态。
- `public/app/console/pages/activity-draft-workspace.js`：正式页面内编辑组件。通过宿主提供的真实接口保存、预览和提交，不含模拟服务；使用共享表单、选择器、抽屉与错误提示。
- `public/styles/activity-workspace.css`：圆角卡片、操作区、表单及岗位表格样式。公共导航通过 admin.css 的 `--nav-w` 引用统一的 200px 变量，各管理页面一致；活动目录为 250px。

## 仍需接入

已增加开发入口 `/console/events?workspace=v2`，复用真实 console shell。草稿存储和 API 已接入；现有正式活动仍通过原工作区处理。负责人名单、草稿转换、地区审批及发布还需继续接入，提交按钮暂时关闭，不应将本批代码视为完成全部功能。

生产服务默认不开启新草稿 API；只有设置 `PLATFORM_ACTIVITY_WORKSPACE_V2=true` 才开放开发入口所需的草稿服务。合成预览脚本始终提供隔离的内存草稿服务，不读取生产配置、不写真实 NJUTable。

真实服务将草稿存入 `PLATFORM_WRITE_STATE_DIR/activity-workspace-<数据源摘要>.sqlite`。该文件包含内部活动内容，不能放入静态资源目录、源码或公开备份；备份、恢复和发布保留规则与该私有目录一致。SQLite WAL 模式应使用一致性备份或停止服务后备份，不能在写入中仅复制主文件。

草稿 API 当前仅允许当前作者操作自己的私有草稿，不授予主席团全局查看、审批或发布权限。有组织权限证据时，选择类别仍需通过现有类别创建权限校验。地区主席团的正式业务权限将由可信名单单独绑定，不通过当前私有草稿接口绕过。

持久化已使用私有 SQLite 与统一草稿队列。存储更新通过事务及版本条件检查拒绝独立连接的旧版本写入；同一作者的创建标识有唯一约束，重试不会另建草稿。不能在页面组件中使用 localStorage 替代正式草稿持久化。

提交计划的应用必须在同一权威写入边界内重新核对当前版本、最新预览摘要、账号名单与地区权限；不能先读取计划、等待其他操作后直接照旧应用。

## 账号与地区

南京与苏州的主席团、中心主任组织名称一致，不通过名称是否包含“苏州”判断地区。使用账号名单的地区、角色、中心证据绑定，客户端传入的身份不能作为授权。

当前缺少已验证名单时，`workspacePermissions` 返回拒绝。只允许本地区主席团处理对应活动审核，本地区本项目负责人编辑草稿；其他中心或地区主任不得因此获得编辑权限。

名单提供者需要返回当前有效的 `actor`、`verified`、`active`、`region`、`role`、`categories`。这些值只能由服务端从可信名单构建，不能直接接受表单字段。

`workspace-roster.js` 提供可信名单适配边界：以稳定账号 ID 与活动所属地区共同查找，完整名单中必须唯一命中且仍有效。主任团还需匹配中心及活动负责人；主席团仅获得本地区权限。相同组织名称、全局管理员标签、缺失或重复名单均不能代替地区证据。此适配器尚未接入实际名单来源，不能因此宣称已开放地区审批。

`workspace-approval-routing.js` 已实现可注入现有工作流的地区审批适配器，按完整可信名单分配本地区主席团，绑定地区、类别与申请版本；实际审核时重新读取名单。新增成员不会自动接管旧申请，停用或撤销即时拒绝审核，不回退到旧的全局超管规则。测试已接入真实 `createWorkflow` 验证退回、重提、审批通过后等待发布；生产与开发入口尚未切换到该适配器，仍等待实际名单和草稿转换边界。

类别与既有共享分类常量一致，新增完整名称“排班类”；南京七类、苏州五类。合成预览的审核账号夹具同步包含排班类，不对应真实人员。

## 草稿版本

保存允许空报名方式、空日期与空时长，不设置默认值或编造事实。提交才验证完整信息。岗位 ID 与活动 ID 稳定，复制岗位产生新 ID。

生成预览不等于用户已阅读。显式确认绑定操作者、草稿 ID、版本与完整内容摘要。任何保存递增版本并清空预览确认，提交计划不得跳过该检查。

服务不修改既有活动审批摘要、不产生报名行、不发布、不发送邮件。后续接入必须保留旧活动 ID、报名、签到、时长关联，以及原有不确定结果核对机制。

现有分岗位生成服务已支持每个岗位可选的 `serviceHours`、`trainingHours`、`travelHours`，省略时保留原有继承逻辑；明确设置时写入对应子活动及批准摘要。岗位时长进入岗位定义摘要，重试沿用原 ID，已有报名的岗位不能通过更换时长偷偷改写。新工作区转换尚未接通，不能把这项兼容修正视为已开放提交。
