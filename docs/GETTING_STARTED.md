# 运行与复现指南

## 1. 环境与安装

需要 Node.js 22.13 或更新版本、npm、Git。优先使用 Node.js 24。进入仓库根目录执行：

```bash
node --version
npm --version
npm ci --ignore-scripts
npm run verify
```

`npm ci` 按 `package-lock.json` 重建依赖；检查、lint 和合成测试不读取 `.env`，不访问 SeaTable 或 SMTP。npm 安装需要网络，应用前端无需编译。Windows 可使用 PowerShell；复制配置使用 `Copy-Item .env.example .env`。

## 2. 无凭据界面预览

```bash
npm run preview
```

打开 `http://127.0.0.1:3000`，停止使用 Ctrl+C。若端口占用，macOS/Linux 用 `PORT=3001 npm run preview`；PowerShell 用 `$env:PORT='3001'; npm run preview`。

预览只绑定本机回环地址，不加载真实服务端或业务数据。匿名会话可用，其余 API 明确返回 `503 preview_only`。可查看页面布局、加载和错误状态，无法验收登录、数据统计或业务流程。

## 3. 完整业务测试环境

复制 `.env.example`，已有配置时先备份再编辑。不要使用生产 Token 做新贡献者的测试环境。

| 配置组 | 要求 |
| --- | --- |
| `SEATABLE_SERVER_URL` / `SEATABLE_API_TOKEN` | 独立业务 Base；默认 URL 是学校服务，新部署可配置自己的 SeaTable |
| `PLATFORM_SESSION_SECRET` | 至少 32 字符随机密钥，例如下方生成命令 |
| `SEATABLE_IDENTITY_API_TOKEN` / `SEATABLE_IDENTITY_BASE_UUID` | 独立私有身份 Base；设置后账号表不可达或为空会阻止启动，避免凭据兜底 |
| `SEATABLE_BUSINESS_BASE_UUID` | 业务关联使用的 Base UUID |
| `SEATABLE_VOLUNTEER_*` | 可选，志愿数据只读连接 |
| `SEATABLE_PROFILE_*` | 可选，明确指定的资料写连接；不可与只读报表连接混用 |
| `SMTP_*` | 生产注册/重置所需；开发不配置时验证码进入服务端日志 |
| `NJUBOX_*` | 可选，附件能力；未配置不具备上传能力 |

生成密钥：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

最小本地兼容模式可以留空 `SEATABLE_IDENTITY_API_TOKEN` 和 UUID，使用业务 Base 与本地账号文件；这只用于隔离测试环境。`.env.example` 默认指向账号文件，文件必须存在且非空：

```json
[
  { "username": "local-admin", "password": "ChangeMe-Local-Only-123!", "role": "platform_admin", "label": "本地测试管理员" },
  { "username": "local-member", "password": "ChangeMe-Local-Only-456!", "role": "member", "label": "模拟成员" }
]
```

将该合成示例保存为 `.platform-accounts.json` 并自行替换口令。若采用单账号环境变量兜底，需将 `PLATFORM_ACCOUNTS_FILE` 留空，设置 `PLATFORM_ADMIN_USERNAME` 和密码。已配置私有身份 Base 时，上述兜底不会启用；应由维护者初始化私有账号表。生产配置必须使用独立私有身份 Base。

## 4. 表结构与数据准备

项目依赖现有物资、活动、志愿及身份数据模型，不是“一条命令创建全部业务数据”的通用 SaaS。底表关系参见 [专项架构](../PLATFORM_ARCHITECTURE.md)、[物资说明](../MATERIALS_MODULE.md) 和 [资料映射](../VOLUNTEER_PROFILE_MAPPING.md)。仓库不附真实数据导出。

先在测试 Base 运行需要的只读预览：

```bash
npm run events:dry-run
npm run state:dry-run
npm run accounts:dry-run
npm run notices:dry-run
npm run profile-mapping:preview
```

预览需对应 Token；最后一项针对私有身份表字段。私有身份迁移工具以已有合法账号为输入，并非空 Base 的账号生成器。参见 [脚本分类](../scripts/README.md)，由维护者核对目标 Base、备份和授权后执行必要迁移。不要为了让页面显示数据而导入真实同学资料。

## 5. 启动与验证

```bash
npm start
# 或监视模式
npm run dev
```

服务启动日志会显示账号来源和邮件通道。用另一终端执行：

```bash
npm run smoke:public
```

此时默认检查 `http://127.0.0.1:3000`。其他端口使用 `SMOKE_BASE_URL=http://127.0.0.1:3001 npm run smoke:public`（PowerShell 先设置环境变量）。其余 smoke 的地址变量为 `BASE_URL`，默认端口见测试指南。

## 常见问题

- `Missing SEATABLE_API_TOKEN`：真实服务需要 Token；无凭据请使用 `preview`。
- 私有身份启动失败：核对 UUID、访问权、账号表与账号状态；不要删除私有配置来绕过安全边界。
- 预览 API 的 503：预期行为；完整业务接口需独立数据环境。
- `EADDRINUSE`：检查端口所属实例或更换端口，避免把冒烟测试跑到错误服务。
- 生产邮箱无法注册：检查 SMTP 通道；生产禁用控制台验证码兜底。
- `403`：先区分应用权限/CSRF 与上游数据源认证失败，不能仅凭状态码归因。

## 6. 志愿活动试点

`npm run preview:workflow` 在3121端口提供合成管理员/学生界面。真实测试副本需显式启用 `PLATFORM_TEST_WORKFLOW`，且配置 UUID 与认证返回均符合代码指定值；默认关闭。详见 [试点运行](WORKFLOW.md)。生产照片使用独立目录和权限，不复制到 `public/`。

当前线上版本与本地开发不能仅通过Git HEAD推断；来源与依赖见 [线上基线](PRODUCTION_BASELINE.md)。新维护者不应为复现而运行写入联调或清空表。
## 本地会话撤销存储

退出登录会先持久化会话撤销记录，再返回成功。默认文件为仓库目录下的
`.session-state/revocations.json`，该目录不提交到 Git。文件仅保存会话标识的
SHA-256 哈希及过期时间；过期记录在后续保存时清理。

可通过 `PLATFORM_SESSION_REVOCATIONS_FILE` 指定文件位置。生产部署必须使用
位于代码发布目录之外的持久私有目录，并由服务账号限制访问权限。

记录文件损坏或读取失败会阻止启动；保存失败时退出接口返回 503，
不会返回退出成功或清除 Cookie。

首次运行允许文件不存在。因此，删除记录文件或丢失存储卷会丢失撤销历史；
不要通过删除文件解决启动错误。无法恢复撤销历史时，应更换
`PLATFORM_SESSION_SECRET`，使现有会话全部失效，用户需重新登录。

此实现只支持单进程写入。它不提供多实例协调，也不代表已经完成断电、
磁盘故障或备份恢复验收。

## 外部请求超时与取消

应用 API 默认使用 30 秒共享预算，包含队列等待时间。
SeaTable、NJUBox 和 SMTP 外部操作默认还有 15 秒截止时间。
请求超时或客户端连接中断后，取消信号传递到外部操作，
预算失效后不再开始新的外部请求。

SeaTable SDK、直接照片上传、NJUBox 请求均覆盖响应内容读取。
SMTP 为每封邮件创建独立连接，取消时关闭对应连接。
不完整的请求体上传超时后会终止连接，客户端可能收到连接中断。

写入队列等待当前任务结束及清理完成后才释放，不通过提前返回制造并发写入。
共享认证和展示缓存独立于单个用户的取消信号，调用方可单独停止等待。
后台密码重置任务使用独立预算。

超时或取消不表示用户登录失效，也不能回滚上游已经完成的写入。
写入结果可能未知，不自动重试，应先核对记录或文件。

SeaTable 保护依赖 SDK 所用 Axios 的默认适配器，
升级 SDK 或 Axios 后须重新运行兼容性测试。
未经保护入口初始化的独立运维脚本不属于本次覆盖范围。

合成测试覆盖超时、连接取消、队列恢复、共享请求隔离、
后台任务隔离、上传读取及 SMTP 握手停滞。
尚未完成真实 NJUBox 上传、真实 SMTP TLS 登录投递、生产容量和线上部署验收。
预算依赖异步操作响应取消，不会强行中断同步计算或回滚本地文件写入。


## 物资恢复凭证与共享写锁

本地开发默认将操作凭证与共享锁保存在仓库根目录的 `.write-state/`，
该目录不提交到 Git。可通过 `PLATFORM_WRITE_STATE_DIR` 指定目录。

生产必须显式配置持久化私有目录。同机参与进程应使用相同路径，
目录不得放在 `public/` 下。不要为了重试操作而删除未完成凭证。

恢复接口、人工核对条件、备份要求与同机协调边界见
[物资写入与恢复说明](../lib/materials/README.md)。

逾期提醒使用有超时保护的 SMTP 调用，并接入共享写锁。
邮件发送与发送记录写入仍不具备原子性，重复投递问题需另行处理。

## 账号候选查询

登录解析及已登录请求中的账号刷新，优先使用 SeaTable SQL 筛选候选行，
再由身份存储层执行原有账号匹配和权限判断。

登录匹配优先级仍为登录名/邮箱、学号、真实姓名。
同一优先级存在多个有效账号时，登录解析返回冲突，不任意选择账号。

候选查询每页 100 行，按行标识排序。
结果格式错误、重复行、超过安全读取上限或上游查询失败时停止请求，
不将失败视为空结果，也不使用缓存凭据继续认证。

含引号等不适合直接生成查询的旧标识，以及没有 query 接口的离线客户端，
保留原有分页读取兼容路径。SQL 请求失败不会触发这个兼容回退。

测试环境可运行只读兼容性检查：

```powershell
node --env-file=.env scripts/preview-account-query.mjs
```

检查使用私有身份连接并核对 Base UUID，不修改账号，
输出不包含 Token、邮箱、密码哈希或账号内容。

### 优化边界

本次减少正常账号查找时向应用传输的行数，以及应用中的全表匹配。
不代表 SeaTable 内部查询一定使用索引，尚未完成负载与性能基准测试。

服务启动时的全量账号加载、其他身份表读取及志愿时长对账仍需分别优化。
HTTP 同步密码计算已由异步计算替代；整体容量和性能仍待负载验证。

## 异步密码计算

HTTP 登录、注册、密码重置和修改密码使用异步 scrypt，
保持当前 scrypt 密码存储格式，已有标准哈希无需迁移。

单进程默认最多同时执行 2 个密码计算，最多等待 32 个。
队列满时返回可识别的服务繁忙错误，不认证请求。

等待任务保留自身请求预算。取消时移除尚未开始的任务；
已开始的计算无法立即终止，仍占用计算名额直到实际结束。
取消或超时后不返回成功的计算结果。

验证前检查哈希格式和计算参数上限。
异常、损坏或超限哈希不能用于认证；未来升级哈希参数时，
需要同步评估验证器的兼容范围和资源限制。

同步工具函数保留用于离线脚本和测试。
本次不代表所有维护脚本已改为异步，也不构成跨进程计算限流。
线程池仍与其他 Node.js 操作共享资源，容量需要通过实际负载测试评估。

## 分页读取与完整性检查

通用分页读取由 `lib/http/paged-rows.js` 提供，默认每页 500 行、
最多读取 5,000 行。达到上限后额外探测一行，以区分恰好达到
上限与仍有未读取的数据。

读取过程检查异常页、重复行标识和上游截断标记。需要完整数据
的统计和写入判断，在结果不完整时拒绝继续，不使用局部数据
计算完整统计或授权写入。

活动通知和附件列表使用完整分页读取；物资、活动、志愿及公众
首页汇总检查来源完整性。状态表读取不再把数据源失败处理为空表。
审计读取和通知汇总也不再把读取失败呈现为没有记录或通知。

超过读取上限可能返回数据不完整错误，应评估按条件查询或专用
统计接口，不能仅通过取消检查恢复页面。

这些检查不提供数据库快照或跨表事务；读取期间数据变化仍需
由业务协调机制处理。合成测试通过不等于生产容量验收。

身份表全量读取也使用统一分页检查，每页 100 行，上限 100,000 行。
恰好达到上限时通过额外一行探测确认完整性；超出上限、上游截断、
重复行标识或异常响应会阻止身份判断继续。读取失败不会作为空表处理。
这不改变账号过滤查询，也不代表生产容量已经验收。

志愿流程表和献血岗位同步也使用统一分页检查，每页 500 行，
上限 100,000 行。上游截断、异常响应和重复行标识会阻止继续处理；
岗位同步必须完成列表读取后，才能选择目标岗位并执行后续写入。

这些检查不提供读取快照或跨服务器岗位抢占保护，也不替代
真实环境的并发与故障恢复验收。

数据中心的 `GET /api/rows` 是前 100 行预览接口，返回
`previewOnly: true` 和显式 `readMeta`。额外探测一行用于判断是否截断；
`readMeta.total` 仅表示本次返回的行数，不是整张表的总行数。
预览结果不能用于完整统计或业务写入判断。

## 签到照片提交失败的处理

照片保存后，如果报名记录写入失败或响应丢失，服务端保留照片，
不立即删除。远端可能已经保存照片关联，删除会造成证据缺失。

保留的文件可能尚未关联报名，必须核对完整报名记录后才能判断。
当前不自动清理这些文件；保留期限、存储配额和孤立文件处理仍待完善。
本地合成测试覆盖提交失败后保留照片，不代表真实环境恢复验收。

## 签到照片只读关联核查

`scripts/inspect-attendance-evidence.mjs` 对完整报名记录和本地照片
文件清单进行只读比较，报告缺失照片及未关联文件，不修改或删除文件。

入口仅支持指定的志愿测试 Base，要求认证返回的 UUID 匹配，
且 `WORKFLOW_EVIDENCE_DIR` 明确配置为私有目录的绝对路径。
运行前必须人工确认该目录属于对应测试 Base；UUID 校验不能证明目录归属。

目录不存在、扫描超限、报名数据不完整或异常照片条目会停止核查，
不会作为空结果处理。输出只包含数量和最多 20 个文件 ID 样本，
不包含姓名、邮箱或照片内容。

报名读取与目录扫描不是原子快照。未关联文件仅供进一步核对，
不代表允许删除；并发上传、保留期限、配额和恢复验证仍需完善。

运行方式：
`node --env-file=.env scripts/inspect-attendance-evidence.mjs`

当前本地默认照片目录不存在，已完成合成测试，尚未执行真实照片关联核查。

核查报告的 `storage` 提供照片文件、其他普通文件及两者合计的字节数。
这是扫描时读取的文件逻辑大小，不代表磁盘实际分配空间，
不包含子目录内容，也不是并发上传期间的原子快照。

文件存在和大小统计不证明照片内容有效或可恢复。
当前只提供用量数据，尚未设置配额、保留期限或自动清理策略。

## 照片文件校验清单

`lib/events/evidence-manifest.js` 提供只读 SHA-256 清单生成函数，
记录 UUID 命名文件的 ID、字节数和摘要，不读取其他普通文件的内容，
不写入或删除文件。

默认单文件读取上限为 4MB，每份清单最多 1,000 个文件、合计 256MB。
这些是核查读取限制，不是上传配额或存储配额。
超限、空文件或读取失败会阻止返回成功清单，不返回局部结果。

清单不是原子快照。文件校验用于比较字节是否一致，不证明照片内容
有效、日期真实或备份能够恢复。当前完成合成和临时文件测试，
尚未提供命令行导出、备份比较或真实恢复验收。

`lib/events/evidence-comparison.js` 比较两份有效清单：第一份为预期，
第二份为实际。它报告缺失、大小或摘要变化，以及额外文件，
不修改清单、不授权删除，也不执行恢复。

`exactMatch: true` 仅表示两份清单中的文件 ID、大小和 SHA-256
摘要一致，不证明清单来源可信、照片有效或网站能够成功恢复。
当前已完成合成比较和临时文件复制比较，真实备份恢复仍待验收。

### 清单命令行入口

两个入口均不加载 `.env`，要求明确提供绝对路径。
它们不修改照片、不执行恢复，也不授权删除文件。

导出指定私有目录的清单到标准输出：

```powershell
node scripts/export-evidence-manifest.mjs --directory="D:\PrivateEvidence"
```

比较两份已保存的 JSON 清单：

```powershell
node scripts/compare-evidence-manifests.mjs --expected="D:\PrivateReports\expected.json" --actual="D:\PrivateReports\actual.json"
```

比较退出码：0 表示清单完全一致；2 表示比较完成但存在差异；
1 表示参数、文件读取或清单验证失败。

比较报告只展示每类最多 20 个文件 ID 样本，并提供完整差异数量。
清单文件应保存在私有位置，不提交到 Git。
保存标准输出时应使用 UTF-8，并检查退出码及 JSON 有效性；
Windows PowerShell 5.1 的默认重定向编码不适合直接保存本工具的清单。

当前验证使用合成数据和临时文件，尚未执行真实照片备份恢复。

导出时可通过 `--output` 保存 UTF-8 JSON，避免手动重定向的编码问题：

```powershell
node scripts/export-evidence-manifest.mjs --directory="D:\PrivateEvidence" --output="D:\PrivateReports\evidence-manifest.json"
```

以上路径仅为示例。输出必须位于照片目录之外的私有目录，
目标目录须已存在，目标文件不得已存在。

保存前完整生成并验证清单，通过同目录临时文件写入、同步后发布，
拒绝覆盖已有目标。不支持硬链接的文件系统会报错，不回退到覆盖写入。
保存失败时应核查目标状态；进程异常终止可能留下临时文件。

该方式不代表断电持久性或备份恢复已完成验收。
清单包含照片文件 ID，应按私有资料保存，不提交到 Git。

## 审计写入状态

`GET /api/audit/status` 受控制台 `settings` 权限保护，
返回当前进程的写入尝试、已确认和未确认数量及最近时间，
不返回审计事件内容或上游错误详情。

未确认表示没有收到成功响应，不一定代表远端记录未写入。
后续成功不会清除之前的未确认计数；当前不自动重试，
以免响应丢失时重复写入。

计数仅保存在内存，重启会清零，不能替代持久化补偿、
外部告警或审计记录完整性核对。接口仍经过现有身份刷新检查。

本轮合成回归和公开冒烟通过；因当前账号无相应权限，
有权限账号的真实状态读取尚未验证。不得为验证绕过权限。

合成回环 HTTP 测试复用控制台角色与权限守卫，验证拒绝和允许路径，
以及状态响应不缓存、不暴露原始错误。测试注入合成会话，
不替代真实 Cookie 校验、身份 Base 刷新或有权限账号的实际查看。

## 审计持久化凭据与人工核对

`PLATFORM_AUDIT_RECONCILIATION_ENABLED=false` 默认关闭。
关闭时沿用原有审计写入方式与进程内状态统计。

启用需要明确配置 `SEATABLE_BUSINESS_BASE_UUID`、
至少 32 字符的 `PLATFORM_SESSION_SECRET`，并使用受保护的
`PLATFORM_WRITE_STATE_DIR`。启用时必须显式填写状态目录，
配置路径不能位于 public/ 或其子目录；配置检查在创建状态数据库前执行。
启用时还会检查已有祖先目录，拒绝符号链接、非目录路径，
以及实际位置位于公众静态目录中的状态目录。
共用状态目录中已有的数据库及 SQLite 辅助文件必须是普通文件，
不能是符号链接、目录或具有多个硬链接的文件。

检查不创建目录、不读取数据库内容，且只在启动时执行；
它不能防止检查后路径被替换，也不替代目录权限、部署挂载、
SQLite 一致性备份及恢复核验。
本地凭据保存在该目录下的
`audit-reconciliation.sqlite`；审计内容加密保存，数据库绑定密钥和
业务 Base UUID。已有存储与配置不匹配时拒绝打开。

写入前先保存本地凭据，再尝试远端写入，并读取远端证据核对。
响应丢失、读取失败或内容不一致时，保留未确认状态，
不会自动重复写入。业务操作与审计凭据之间没有跨库事务；
本地存储失败时也不能保证凭据已经保存，应检查状态和服务端日志。

以下接口要求控制台 settings 权限：

- `GET /api/audit/status`：进程内写入状态及本地凭据数量。
- `GET /api/audit/receipts?limit=20&after=...`：
  按编号分页列出尚未确认的凭据，每页最多 100 条。
- `POST /api/audit/receipts/:auditId/reconcile`：
  需要 CSRF，读取远端证据并核对指定凭据，不补写远端记录。

列表只返回编号、状态和更新时间，不返回审计内容。
核对未找到远端记录时仍需人工处理；重复编号、内容冲突或不完整
读取不能作为确认依据。prepared 状态即使找到远端记录，也保留
人工核验要求。

常规审计编号通过固定表、固定字段的 SQL 查询读取最多两条候选记录，
用于区分不存在、唯一记录和重复编号，再核对时间与完整内容。
编号只允许安全字符进入 SQL；特殊历史编号或不支持 query 的客户端
使用完整分页读取，读取上限为 100000 行。

SQL 查询失败、不完整或返回异常数据时停止核对，不退回全表扫描，
也不将失败解释为没有记录。查询不使用本地缓存。
此优化减少返回和传输的数据量，不保证 SeaTable 内部使用索引；
真实查询契约和大表性能仍需只读验证。

状态目录属于私有持久化数据，不能放在 public/ 下。
备份应使用 SQLite 一致性备份方式，并单独保护恢复所需的密钥。
不要在服务运行时只复制 sqlite 主文件而忽略 WAL。
更换会话密钥需要先规划已有凭据的恢复，不能直接删除数据库绕过
密钥或 Base 不匹配检查。

本轮通过合成测试；尚未完成真实权限账号下的接口验收、
真实审计表写入与故障恢复演练，以及生产容量和备份恢复验收。

测试环境可执行只读查询兼容性检查：

~~~powershell
node --env-file=.env scripts/preview-audit-query.mjs
~~~

脚本校验业务 Base UUID，检查空候选查询及最多一个已有样本，
不写入远端记录或修改本地凭据，不输出审计内容。
样本检查通过不代表全表无重复，也不代表容量或故障恢复验收。

## 共享私有状态目录检查

服务启动时始终检查 PLATFORM_WRITE_STATE_DIR 对应目录，
不依赖审计持久化功能是否开启。本地未配置时检查默认 .write-state；
生产仍要求显式配置持久化私有目录。

检查在物资凭据、共享写锁和邮件状态数据库初始化之前执行。
拒绝公开静态目录、符号链接祖先、非目录路径，
以及已有数据库和 SQLite 辅助文件中的链接或非普通文件。
检查本身不创建目录、不读取数据库内容。

这是启动时检查，不能阻止检查后目录被替换，
也不替代目录权限保护、备份恢复及部署挂载核验。
发现不安全配置时应修正路径和权限，不能删除业务凭据来绕过检查。

## 本地只读配置检查

在仓库根目录运行：

~~~powershell
node --env-file=.env scripts/check-local-configuration.mjs
~~~

工具检查基本凭据格式、生产所需 UUID 和私有存储配置、
部分功能开关及 SMTP 配置完整性，并只读检查状态目录与
会话撤销文件的位置和文件类型。

不连接 SeaTable 或 SMTP，不创建状态目录、数据库或会话文件。
输出只包含字段名、问题代码和检查状态，不输出配置值。
退出码 0 表示已实现的检查通过；存在错误时退出码为 1。

开发环境未配置 SMTP 会产生 development_console_transport 提示，
不代表真实邮件已经投递。local_bootstrap_only 表示未配置私有身份连接，
仅适用于隔离本地测试。

检查通过不证明 Token 有效、账号可登录、目录可写、
所有配置项均正确或备份可恢复，也不替代启动检查及业务验收。

## 签到照片的服务端有效性检查

新上传的签到照片使用 sharp 完整解码校验，仅接受静态 JPEG、
PNG 和 WebP。损坏、截断、格式不支持或多帧图片会被拒绝。

限制：
- 上传文件最多 4MB。
- 宽和高各最多 6000 像素。
- 总像素最多 1200 万。
- 单个进程最多同时执行 2 个解码任务，最多等待 4 个任务。
- 解码设置 5 秒处理时限；排队另受请求取消和超时约束。

已开始的解码在请求取消后仍可能继续计算，
队列须等实际任务结束才释放名额，不能把取消视为计算立即终止。
解码通过后才创建照片目录并保存原始文件，不改写原始照片内容。

这些检查不证明照片拍摄日期、内容真实性或签到归属，
也不清理、重写或补验已有照片。

sharp 是原生依赖，安装需保留 optional dependencies。
应在目标系统按 lockfile 安装并验证加载，
不能把 Windows 的 node_modules 直接复制到 Linux。
当前本地验证不替代目标服务器的安装和容量验收。

## 队列与容量边界

当前默认限制：
- 密码计算：每进程最多同时执行 2 个任务，最多等待 32 个任务。
- 图片解码：每进程最多同时执行 2 个任务，最多等待 4 个任务。
- 共享写锁：每个协调器实例最多接纳 64 个未完成请求。
- 邮件后台：每轮最多修复 5 条发送记录、处理 5 条投递任务。

等待中的密码计算、图片解码和写锁请求受到取消与超时约束。
计算已经开始时，请求取消不意味着计算立即终止，
必须等实际任务结束再释放计算名额。

队列拥塞不会授权自动重试已经发生的业务写入或邮件投递。
邮件批次取消后保留已预留的尝试次数和未处理任务，
后续根据持久化发送状态决定是否继续，已确认发送的邮件不重发。

这些限制和测试提供本地资源保护，
不证明目标服务器的吞吐量、内存上限或业务高峰容量。
多进程总资源仍需按实例数量评估。

## HTTP 输入与错误响应边界

使用统一 JSON 读取入口的接口最多接受 64KB 请求体。
非空请求体必须是有效 UTF-8 编码的 JSON 对象；
null、数组、标量及非法 JSON 返回 400。
空请求体继续按空对象处理。
超过大小限制会被拒绝；连接行为取决于请求流状态。

未知异常和服务端 5xx 不向浏览器输出原始错误信息。
明确的业务 4xx 保留用户提示，因此新增业务错误仍须避免敏感内容。
上游认证失败保持数据服务不可用分类，不误判为用户登录失效。

志愿流程的来源检查要求 HTTP/HTTPS 协议及匹配的主机和端口。
来源检查不替代登录、权限、CSRF 或本人归属检查。
未携带 Origin 的客户端仍须通过对应身份与 CSRF 校验。

## 后台定时任务的停止边界

逾期提醒使用单次运行调度器，同一调度器实例不会重叠执行。
任务或日志处理失败后，运行名额会释放。

HTTP 服务关闭时停止相关定时器的后续触发。
已经开始的操作允许完成，不将停止视为远端写入已取消。
这些修改不构成完整的 SIGTERM 优雅退出或跨服务器任务协调。

账号加载及逾期提醒的相关失败日志采用固定提示。
开发环境控制台邮件通道仍按既有设计输出邮件内容，
不能用于生产或作为真实邮件投递证明。

## API 路径编码检查

API HTTP 入口在业务分发前检查路径编码。
损坏的百分号编码、无效 UTF-8，以及解码后的空字符或控制字符返回 400。
错误响应不回显提交的路径。

检查只验证路径，不改写路由或业务标识。
活动通知的路径尾部仅解码一次，避免误拒绝百分号标识，
或将包含编码文本的标识转换成另一条记录的标识。

## 资料同步的查询结果检查

资料同步按已验证学号查询固定资料表，最多读取三个候选结果。
显式截断、结果结构异常、缺少行 ID、重复行 ID 或学号不匹配时，
停止自动同步并进入待重试状态。

查询失败或截断不能当作“没有资料”，不能据此创建源资料行。
私有待同步内容会保留，允许后续在有效查询结果下重试。
多个不同候选或姓名不匹配仍进入人工核验流程。

这些检查针对已识别的返回结构和截断标记，
不替代真实数据源的查询兼容性及完整性验收。

## 岗位详情资料查询并发

献血车岗位详情每次读取最多并行执行四个岗位资料查询，
返回结果保持原岗位顺序。

查询失败、截断或请求取消后，停止启动后续查询，
并等待已经开始的查询结束。
资料姓名不匹配或存在多个候选时，不覆盖原岗位人员字段。

此限制按单次读取计算，不是整个进程或多个实例的全局上限。
它限制并发数量，不代表所有岗位只需一次查询，
也不替代真实环境的延迟和容量测试。

## 签到照片清理预览

后端提供三个只读模块：

- `evidence-cleanup-directory.js`：有数量上限地读取目录元数据，
  不读取文件内容、不进入子目录，拒绝以符号链接或目录联接作为扫描根目录。
- `evidence-cleanup-preview.js`：根据引用记录、文件类型、链接数量和修改时间，
  生成待人工核验的候选清单。
- `evidence-cleanup-inspection.js`：先检查引用记录，再读取目录；
  引用读取失败、截断或格式异常时停止预览。

调用方必须确认引用来源完整，并显式传入当前时间和最小文件年龄。
最小文件年龄是本次预览的筛选参数，不代表平台已确定保留期限；
文件修改时间也不等同于照片拍摄或提交时间。

结果始终标记为只读、零写入、零删除和未授权删除。
引用记录与目录扫描不是原子快照，完整性标记由调用方提供。
候选文件仍需人工核验，不能据此直接执行删除。

已覆盖合成目录、硬链接、目录联接或符号链接、扫描上限、
引用读取失败和截断等回归测试。尚未提供自动清理命令、
正式保留策略或生产环境清理验收。

## 服务退出与请求取消

服务收到 SIGINT 或 SIGTERM 后，先停止活动快照、空位提醒、
邮件后台处理和物资逾期提醒的后续调度，再停止接受 HTTP 连接。

已有 HTTP 请求最多等待 10 秒；超时后关闭连接并设置非零退出码。
连接中断会传递请求取消信号，但取消不能保证外部写入未发生，
结果不确定的操作仍应按恢复凭证核对。

退出处理不直接调用 process.exit()。已经开始的后台任务可以继续收尾，
因此 10 秒仅是 HTTP 连接等待上限，不是整个进程的退出上限。
目前没有跨后台任务的统一完成追踪或整个进程的强制退出期限。

本地合成测试覆盖真实 HTTP 断开、队列容量释放、正常 HTTP 收尾、
超时连接关闭、重复信号以及独立子进程退出。
Windows 子进程测试通过触发进程内信号事件验证接入逻辑；
不代表生产操作系统信号、systemd 停止行为或真实业务写入的验收。
