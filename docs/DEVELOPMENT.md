# 开发约定

## 风格与模块

使用 JavaScript ES Modules，2 空格缩进、UTF-8、LF 与末尾换行；由 `.editorconfig` 提示。模块路径显式包含扩展名。页面文件使用 kebab-case，共享工具放 `core/` 或 `ui/`，后端领域代码放 `lib/<domain>/`，运维脚本放 `scripts/`。不要用纯格式化修改混入业务修复。

`eslint.config.js` 采用 recommended 正确性规则，区分 Node 和浏览器全局；暂未启用未使用变量和无效赋值规则以避免大范围遗留清理。控制字符正则用于输入过滤；SDK 异常边界刻意抑制可能含凭据的 cause，因此这两类规则作了显式例外。语法和相对导入另由 `check` 验证。当前没有类型检查或自动格式化门槛。

## 功能变更步骤

1. 找到对应领域模块、页面、API 与表结构。
2. 实现最小必要修改，保持调用边界；显式注入外部服务以便测试。
3. 涉及权限、并发或持久化时，覆盖成功、失败和拒绝路径。
4. 更新相关模块 README 与指南。
5. 执行 `npm run verify`，必要时在独立测试环境做业务冒烟。
6. PR 说明触发场景、变化、验证与残余风险。

分支建议 `codex/<short-topic>` 或团队约定的功能分支。依赖变更提交 `package.json` 与 lockfile，写清升级原因、兼容性证据。禁止直接手改 lockfile 中的解析结果。

## 前端

API 调用集中在 `core/api.js`；渲染使用 DOM 工具，用户内容用文本节点/安全投影。保持 CSP，不新增远程脚本或内联事件。颜色、间距和动效优先使用 `styles/tokens.css`。页面覆盖 loading、empty、error 和结果态，保留键盘焦点与减少动画支持。界面隐藏敏感字段不能替代服务端投影。

## 后端与脚本

权限检查先于写入。业务字段使用明确白名单；错误信息不回显上游 Token、口令或原始资料。Schema 工具默认预览，执行模式保留备份、目标 UUID 核验和后置验证；新增工具应使用显式 `--apply` 与确认短语。旧工具的保护不完全一致，详见脚本 README，不能假设所有工具行为相同。

## 文档维护

持续指南放 `docs/`，短期方案或结果放日期性报告。报告注明检查范围、环境、命令、通过/失败与未验证项。不要把历史线上验证、合成数据测试或界面预览写成当前业务验收。
