# 普通活动名额与报名通知

## 数据职责

`网站活动流程表` 的普通班次容量与 `网站活动报名总表` 的有效报名记录共同决定剩余名额。报名总表只记录真实人员历史，不创建空白人员行；请假批准后原报名记录仍保留，再次报名生成新的报名编号。

`网站普通活动名额表` 是系统维护的名额清单：每个活动 ID 的第 N 个名额使用稳定的 `活动ID:N` 编号，记录日期、地点、时段、岗位、序号以及关联报名编号/行 ID。状态为“空闲”“已占用”“取消待审批”“已停用”。容量减少时保留多出的历史位置并停用，不删除。取消待审批仍占名额。献血车继续使用原排班底表，本表仅覆盖普通班次。

名额清单不是独立报名权威源。直接修改其占用状态不能新增、取消或阻止报名；应通过活动容量和平台报名/请假审核操作。后台每分钟在工作流写队列中重读并对账，允许短暂展示延迟，不在每次报名请求中重建全部名额。单进程队列并非 SeaTable 跨客户端事务；多实例部署前需引入统一写协调机制。

## 自动确认通知

`网站报名通知任务表` 保存通知意图、正文、目标邮箱、去重键、尝试次数与下次尝试时间，仅服务端与有底表权限的管理人员可访问。

- 普通活动直接确认和献血车岗位正式确认后，后台扫描创建任务。待筛选、岗位未同步、取消待审批和名单发布中不能发送成功邮件。
- 筛选名单仍从名单确认工作台发布，发送器接入同一通知任务层；这类任务的重试仍从工作台发起。
- 幂等键沿用 `WF-RESULT:报名ID:yes/no[:名单版本]`。新报名编号代表新的报名，不复用被取消的旧记录。
- 已保存的任务先标记“发送中”，再调用 SMTP。成功接受后标记“已发送”；SMTP 接受不等于收件箱投递成功。
- 已知连接失败或 SMTP 拒绝允许指数退避，最多五次；超时、调用异常或进程中断进入“结果待核对”，不自动盲目重发。每轮最多处理十个自动任务。
- 邮件不可用不会撤销报名；任务保留待发送。开发 console 通道不能作为通知成功凭据。
- 报名成功邮件含日期、时段、地点、岗位、报名编号及详情链接，说明取消须管理员批准，时长以核验后正式录入为准。

当前管理端尚无独立通知任务工作台；重试耗尽和结果待核对由运维核对任务表及 SMTP 接受证据，禁止简单批量重置任务。不得把通知表或正文通过公共接口返回。

## 迁移和启用

先运行 `scripts/migrate-registration-operations.mjs` 预览。使用正式服务端环境配置，工具校验工作流 Base UUID，仅输出数量和摘要。写入要求 `--apply --confirm=REGISTRATION-OPERATIONS --digest=<当前预览摘要> --backup=<不存在的绝对私有目录>`，备份目录 0700、文件 0600，不进入 Git。

迁移只新增两张系统表、预留普通活动名额，并为已有已确认/已签到记录设置“历史未补发”基线，不修改报名总表，不调用 SMTP。重试须重新预览，不重复初始化历史基线。业务并发变更导致摘要或最后核对不符时停止，核对后再运行，不能覆盖新增报名。

部署源码后再分别设置 `PLATFORM_ORDINARY_PLACES=true` 和 `PLATFORM_REGISTRATION_NOTIFICATIONS=true`。通知需要迁移基线及生产 SMTP 配置；默认两个开关关闭。只支持当前单个 Node 服务实例，不允许多个 worker 同时消费。关闭开关可停止后续同步/通知，不能撤回已接受邮件，也不删除历史数据。

生产验证只读检查名额数量、占用关系、通知基线和服务发布清单。真实邮件验收使用明确获准的收件人，不创建虚假生产报名，不向历史报名者群发测试信。
