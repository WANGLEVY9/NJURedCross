# 内建板块 SeaTable 查询

早安晚安与生日祝福通过 `lib/community/scoped-rows.js` 共享条件查询。业务数据使用管理 Base，早安晚安账号补充信息使用身份 Base；表名和查询列由服务端白名单确定。原有功能开关、表结构检查、会话与权限检查继续在业务入口执行。

## 查询范围

| 场景 | 子表与定位条件 |
| --- | --- |
| 本人名片、退出、重新报名 | 早安晚安名片表：账号ID；黑名单表：账号ID |
| 广场列表/详情 | 名片表：本人账号，或已发布状态/目标名片ID；保留公开字段投影、标签筛选与六张分页 |
| 好友邀约与反馈 | 名片表：发起人账号和目标名片ID；邀约表：邀约ID；身份库账号表：账号ID |
| 名片修订 | 修订表：名片ID和账号ID；审核详情与锁内重读：修订ID及关联名片ID |
| 名片审核、拉黑、解除、历史举报处理 | 对应名片ID、账号ID、黑名单ID或评论ID；举报列表只关联被举报名片 |
| 生日本人投稿与参加记录 | 投稿表：项目和提交人；参加表：来源及本人标识，兼容原有历史标识匹配范围 |
| 收到的生日祝福 | 先查本人学号的已投递记录，再按投稿ID批量查祝福库、投稿和本人的举报，最后读取作者的参加记录 |
| 发出的生日祝福 | 先查本人来源投稿，再查关联投递及收件人的参加昵称；沿用原有隐私投影 |
| 生日修改、删除、审核、入库、举报处理 | 按投稿ID、登记ID、举报ID定位，归属和状态检查继续保留 |
| 生日黑名单检查与恢复 | 参与者标识或学号；兼容账号ID、登录名和学号 |
| 生日写操作租约 | 操作锁表只读取当前锁键，竞争、清理、重读和释放保持原协议 |

管理端全局统计、完整成员列表、标签词典和生日全局匹配/投递仍按业务所需读取完整集合。广场列表先在数据库中过滤已发布名片，标签匹配和分页保留现有应用层规则。标签去重继续保持大小写不敏感的历史规则。

## 查询与完整性

- 调用方传结构化条件：对象内为 AND，对象数组为 OR，字段值数组为 IN。表名、列名和操作符不能由浏览器指定。
- 使用现有 SDK 的 `query(sql)`，固定子表、列及排序表达式。每批 IN 最多 100 个值，每页最多 100 行，按 `_id` 稳定排序，并探测上限之外是否还有记录。
- 早安晚安沿用 5000 条读取上限；生日沿用 `WARMTH_STATE_MAX_ROWS`。重复行、异常返回、超限或截断立即停止，避免以部分记录判断额度、黑名单或审核状态。
- 空关联集合直接返回空结果；SQL 查询失败返回脱敏错误，保持失败可见。
- 安装的 SDK 查询接口没有绑定参数入口。查询构造仅接收经过校验的值；含引号、反斜线、控制字符、反引号、空值或过长值的历史标识走原有有界完整读取和精确过滤。缺少查询接口的合成客户端也使用该兼容路径。
- 写入判断和锁内重读直接读取权威源；不新增跨用户缓存或持久化索引副本。

本次使用业务键条件定位与批量关联查询。物理索引是否命中由 SeaTable 执行层决定；代码变更不创建数据库索引、不执行表结构迁移。

## 验证

`tests/community-scoped-rows.test.mjs` 覆盖精确子表与条件、跨页、批量关联、空集合、异常结果、注入字符兼容、本人名片和广场隐私。`tests/birthday-scoped-read.test.mjs` 覆盖收件/发件链路、作者历史标识、空收件箱以及作者删除后保留已收祝福的规则。原有早安晚安、生日和租约回归继续运行。

合成验证不连接生产 Base。线上耗时、执行计划与大表负载需在实际环境另行测量。
