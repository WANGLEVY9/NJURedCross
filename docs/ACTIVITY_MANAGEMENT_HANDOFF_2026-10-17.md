## 3. 本轮已实现、已在本地验证的内容

| 交付项 | 实际行为 |
| --- | --- |
| 三步创建活动 | 活动信息 → 岗位安排 → 通知与审批；返回上一步复用原草稿 ID，不重复创建；第三步完成通知后主动提交审批 |
| 默认服务岗 | 整体统一报名可跳过额外岗位配置，使用默认服务岗，继承活动时间、地点和名额；历史空岗位配置仍可读取 |
| 指定审核人 | 网页创建活动的审批和时长审核仅限创建审批快照中指定的审核人；指定多人均可处理；现有超级管理员权限保留 |
| 全局身份不自动获审权 | 仅具备主席团/指导组全局管理身份，未被指定且不是超级管理员，不能审批/审核所有网页活动 |
| 整表完整性检查 | 到场者有有效签到和完整时长；未到场者填写缺席说明；待审批请假仍待处理，已批准请假不计待处理 |
| 缺席登记 | 支持标记、取消缺席；不伪造签到或时长；已签到或已有时长人员不能标记缺席 |
| 真正的整表提交 | 不再把录入第一条时长视为整表提交；全部处理后提交，负责人签到及时长编辑锁定 |
| 整表退回 | 指定审核人填写原因退回后，负责人可修改未通过明细、重新提交；已通过明细不可直接改写 |
| 跨岗位一致性 | 同一网页岗位项目共用整表版本与锁定状态；旧页面版本冲突、不完整证据会被服务端拒绝 |
| 手动收尾 | 整表审核完成后由指定审核人单独结束网页活动；下载不会自动结束；全员请假/无人参加也能提交空表收尾，但不导出空的时长 Excel |
| 诚实的按钮含义 | 显示“导出 Excel”，不再暗示已经自动发送；负责人只读视图不展示审核、退回和导出操作 |
| 私有持久化 | 整表版本、缺席说明、提交/退回记录保存到服务器私有 JSON，不改报名配置批准摘要，不新增远程表列 |

以上“已实现”表示代码和合成验证完成，**不代表已经上线**。原有本人申请/本人时长回避及超级管理员例外规则保留，本轮没有另行设计主席自己申请的业务政策。

新增接口位于 `/api/volunteer/workflow/events/:id/`：

| 方法及后缀 | 用途 |
| --- | --- |
| `GET hours-sheet` | 读取整表版本与待处理情况 |
| `POST hours-absence` | `revision`、`registrationId`、`reason`；`reason: null` 表示取消缺席 |
| `POST submit-hours` | 携带 `revision`，重新核对当前名单及证据后提交 |
| `POST return-hours` | 携带 `revision` 和退回原因，由指定审核人退回 |

服务端判断权限，不接受请求体伪造角色。版本冲突返回 409；私有文件异常停止后台操作，公众活动读取不依赖该文件。
