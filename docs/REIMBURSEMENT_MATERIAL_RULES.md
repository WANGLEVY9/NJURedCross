# 报销材料规范与补充修改（2026-10-27）

本次补充：财务活动分类直接复用活动广场的七类：主席团专项、博爱中心、生命中心、综事中心、排班专项、一加助残专项、献血车专项。旧表“主席团”“一加助残”等按共享别名映射；“苏州分部”仅作为地区线索，不能臆定业务类别。南京地区、南京活动及仙林/鼓楼等同属南京的多校区值均可正确筛选。缺少可靠类别的历史演示活动仍显示未分类，保留其原关联与记录；不会为了展示效果随意归类。类别没有近期活动时仍显示该类别，并提示暂无可选活动。

火车票原件使用申请人填写的出发站、到达站、单程/往返及报销事由，下载名为“姓名-火车票-出发站-到达站（单程/往返）-外出事宜.pdf”。外出事宜取报销事由，OCR 不覆盖这些值。新火车票申请必须填写行程；已有无行程字段的旧记录保留原命名兼容。初审、终审及退回补充可修改并保留该结构信息；已经终审的条目保持冻结。

本次按负责人提供的分类要求及用户后续确认实现。一份新申请对应一笔订单，可包含多项物品。用户须确认单笔订单；系统未将订单号 OCR 当作可靠的跨订单识别。新申请使用 `materialRulesVersion: 1`、`singleOrderConfirmed: true` 和布尔值 `meetingRelated`。服务端正式入口要求当前规则版本；旧记录保持原类别和补充流程。

参加会议时额外要求会议邀请函。飞机与高铁的起终点及价格证明、收货地址、出发地、目的地等业务内容仍须人工核对；材料存在不代表内容已自动验真。订单截图提示订单号、收货地址或打车起终点、商品和金额；付款截图提示付款工具交易明细中的金额、时间、订单号及收款人。付款时间只作为上传说明，本次不自动核验。

发票及行程单要求 PDF 原件；订单、付款、起终点和价格证明可直接上传图片或 PDF。Word 仅作辅助原件，不能替代要求自动核验的截图；原件可下载，不伪造已经合并或识别 Word 的结果。平台沿用统一的申请人、项目、金额、材料类型自动下载名，不改原件字节；新材料类型包含会议邀请函、快递单、快递起终点截图、价格证明和人员名单。

金额核验按类别执行：要求付款截图时比较发票和实付款的较小值；火车票、机票按发票金额核对，不因缺少非必需订单/付款截图而报缺。一笔订单含多项物品时核验整单申报合计，各物品分摊明确交由审核人确认，不把整单匹配冒充逐项金额已经验证。无需订单的类别不显示物资名不匹配；印章检测仍只表示疑似候选，不证明真实性。

## 修改与补充

初审可编辑报销类别及已有申请信息，随初审通过原子保存。终审通过 `POST /requests/:id/edit` 提交 `{revision,stateVersion,changes}`，仅终审权限、本版已初审且待终审的申请可编辑。修改前后值进入审核历史，原申请人、编号、审核归属和原件字节不变；已终审条目冻结。修改使基于旧状态生成的草稿失效，须重新生成并核对。工作台和活动终审均有修改入口；跨活动按稳定申请人账号汇总，不以同名合并身份。

退回邮件中的 `?request=` 定位原申请并进入补充表。附件先展示目录，不下载原始图片或 PDF；默认保留旧附件，可逐份替换、移除或追加。上传接口支持 `revisionSource:{requestId,revision,stateVersion,bundleId,entries}`：条目只能指定一个 `originalIndex` 或 `uploadIndex`，并提供必要的项目与材料类型。服务端仅从本账号、当前待补充申请的当前版本中读取原件，通过既有 Box 适配器校验长度和 SHA-256。拒绝跨账号、任意 URL、重复引用和过期版本。全部保留时可提交零个新文件，但仍生成新材料版本，历史版本不改。旧 3127 预览保留兼容上传路径。

## 活动目录与验收边界

申请人按南京/苏州、活动广场的组织类别、活动名称选择。财务目录单独纳入已经批准且结束的活动，不修改公众报名条件；不接入草稿、未批准或已被替代活动。已有活动目的与内容、明确活动人数带入，缺失时终审补齐，不把容量或报名数推定为实际人数。新申请的近 30 天限制在服务端执行，退回申请可保留原活动；修改为其他活动时重新校验期限。

测试使用隔离合成 Table/Box 和普通 Edge，不写真实表、Box，也不发真实邮件。策划案催补、预算超限、付款时间核验、审核轮换和申请人醒目通知继续暂缓。正式数据读写及实际邮件投递需另行按授权验收。本地常用预览服务须在保留检查点并获准重载后启用这些后端修改。
