# 后端可靠性改动的分阶段接入

本次以 main 为基础进行适配，借鉴 Nport-hut 的 [PR #1](https://github.com/WANGLEVY9/NJURedCross/pull/1)，来源提交 `00908d1b7de12655457aac49eb3c003e919871ab`。保留现有业务、界面、权限与部署工作流，不整分支合并，不覆盖生产环境配置。

## 已接入的保护

- HTTP API 请求预算为 30 秒；外部调用默认 15 秒。客户端断开或预算到期时取消连接及上传。共享认证、显示缓存的加载使用独立预算，一个用户取消不会取消其他用户共用的读取。
- SeaTable SDK、NJUBox、物资图片上传和 SMTP 连接覆盖超时。保留上游认证错误与业务错误的区别，内部异常不回传原始凭据或 SDK 明细。写入超时不自动重试，也不表示远端没有执行。
- 统一分页工具检测无效响应、重复行和截断；身份与流程读取保持原先 100,000 行上限，通用读取保持 5,000 行上限。需要完整数据的操作遇到上限会停止，不能据不完整数据计算容量或执行写入。可选表的缺失仍可降级，截断和请求超时不能降级为空表。
- 在线登录、注册及密码修改使用异步 scrypt、有界计算队列；旧哈希格式保持兼容。离线脚本和合成测试保留同步接口。派生新哈希成功后才消费验证码，避免队列过载提前作废验证码。
- 签到照片完整解码验证静态 JPEG/PNG/WebP，限制 4 MB、1,200 万像素、单边 6,000 像素和解码并发；物资图片沿用 8 MB 上传上限，校验实际字节与 MIME，拒绝重复表单字段。已有照片仍沿用原存储和读取路径。

## 尚未纳入

会话撤销持久化、SQLite 共享写锁、物资持久化恢复凭据、可靠邮件队列和审计持久化需要独立部署设计与恢复验收，本次未接入。当前服务仍不能据此宣称支持多实例一致性或跨表事务。专用服务账号、正式告警和备份恢复也不属于此次代码接入。

## 运行与验收

继续使用项目支持的 Node 22/24，依赖按 lockfile 安装；新增 sharp 原生图片库必须在目标操作系统安装，不能复制 macOS/Windows 的 node_modules 到生产 Linux。

`npm run verify` 覆盖权限、身份及业务回归，并新增取消、共享读取、SDK 超时、密码兼容、完整图片解码、上传边界测试。CI 继续执行桌面/手机浏览器和发布安全检查后自动部署 main。部署后核对发布清单、服务状态、sharp 可加载、公开接口及生产配置未变。

合成测试不连接正式 NJUTable、不发送真实邮件、不写入真实报名记录；真实 SMTP 投递、业务上传及生产容量需要后续独立验收。
