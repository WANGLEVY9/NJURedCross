# 早安晚安同行名片

## 来源与接入范围

本模块选择性复用了徐彧盛（xyshxb@yeah.net）分支 `codex/morning-evening-card`，审核基线为 `2fece79`（2026-10-09 22:29:36 +08:00）。该分支已经包含公众端与管理端；未合并其旧版 server、环境配置、生日模块、全站样式或测试数据。

## 参与流程

1. 注册账号登录，在内建广场或会员中心打开“我的同行名片”。真实姓名、学号、性别必须已在账号资料中补全。
2. 填写公开昵称、校区、最多五个兴趣标签、简介，并选择是否接收评论邮件。
3. 提交后为待审核；具有内建管理权限的管理员可通过、退回修改或拒绝。
4. 已发布名片的成员可浏览其他已发布名片，按兴趣标签筛选并留言。真实姓名、学号、邮箱不在公众名片/评论投影中返回。
5. 留言者可选择邮件通知；仅在收件人允许时发送。联系方式仅在留言者明确勾选后附在通知邮件中，不进入公开评论投影。
6. 本人可举报自己收到的评论；被举报评论立即隐藏，管理员处理。管理员可管理本模块黑名单；解除后仍需重新报名。
7. 已发布名片需先退出，再以新名片提交审核；旧名片和历史评论保留。待审核、退回或拒绝的名片可修改后重新提交。

当前实现是兴趣名片与评论互动，不包含早晚定时匹配、自动群发问候、点赞或聊天系统。


脚本验证生产地址和库 UUID，先保存私有元数据备份，按缺失表/字段追加，可中断后重跑；已有字段类型不符会拒绝执行。备份目录不能发布。
新增表复核后，设置 `WARMTH_MORNING_ENABLED=true` 并重启服务。默认关闭。功能开关开启且字段完整才接受业务请求。回退时关闭该开关，保留数据表。

## 权限、故障与边界

- 所有早安晚安业务接口需要登录；管理接口需要 community 权限，写入复用主线 CSRF、请求预算与限流。
- 通用表写入接口保护四张表，避免绕过名片审核。
- 发布、退出、重新报名、拉黑和留言使用账号互斥；留言写入前重新验证双方状态。等待锁受请求截止时间约束。
- 此锁仅适用于当前单 Node 进程。多实例或绕过 API 直接修改 NJUTable 不受锁协调；扩容前需要共享锁/事务层。
- 全量读取达到截断上限时拒绝继续处理，不把部分数据当完整名单。现阶段未增加私有名片跨用户缓存。
- 数据库业务写入与审计、邮件不是分布式事务。严格审计写入失败可能在业务已保存后返回错误，应先刷新核对再重试。邮件沿用主线服务，不宣称可靠投递队列或恰好一次发送。

## 界面与验证

公众端采用主线品牌页头、字体、主题、分段校区选择和表单组件；名片详情复用桌面抽屉/移动端底部面板，保留键盘关闭与焦点管理。后台在内建管理中分为生日祝福、早安晚安，后者提供名片审核、举报处理、成员管理。

节点测试覆盖权限、隐私投影、审核/举报/限制状态、搜索分页、异步身份查找、失败重报名保留历史、退出与留言竞争、迁移幂等。浏览器测试采用合成接口，覆盖 PC/移动端报名、详情、退出和后台视图，不使用生产 Token、真实留言或真实邮件。
