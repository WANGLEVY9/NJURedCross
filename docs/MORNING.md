# 早安晚安同行名片

## 来源与接入范围

本模块选择性复用了徐彧盛（xyshxb@yeah.net）分支 `codex/morning-evening-card`，审核基线为 `2fece79`（2026-10-09 22:29:36 +08:00）。该分支已经包含公众端与管理端；未合并其旧版 server、环境配置、生日模块、全站样式或测试数据。

## 参与流程

1. 注册账号登录，在内建广场或会员中心打开“我的同行名片”。真实姓名、学号、性别必须已在账号资料中补全。
2. 公开昵称由成员自行填写；性别从账号资料读取并固定展示。校区、最多五个兴趣标签和 100 字以内留言由成员填写，学院与年级可分别选择是否公开。
3. 提交后为待审核；具有内建管理权限的管理员可通过、退回修改或拒绝。
4. 任意已登录的平台注册用户都可浏览其他已发布名片；发起好友邀约时，本人名片必须已经通过管理员审核并发布。真实姓名、学号、邮箱不在公众名片投影中返回。可将喜欢的名片加入心愿单，并在会员中心「温暖连接」中随时查看或移除。
5. 发起邀约仍要求本人名片已发布。邮件标题为「南大红会·早安晚安：您有新的好友邀约」，正文介绍板块并附邀约留言及唯一处理链接，不直接公开发起人邮箱。
6. 收件人使用本人账号打开三天有效的链接，在窗口查看发起人公开名片并同意或拒绝。同意后服务端才返回发起人邮箱，并自动记录成功结识；拒绝后关闭窗口，不计为成功。两种结果均发邮件提醒发起人，采用幂等键与现有加密邮件重试机制；不能撤销或改选，不向指导组发送邮件。
7. 管理员可查看邀约总数、等待反馈数、成功结识数和成功率；管理员仍可管理本模块黑名单，解除后成员需要重新报名。
8. 已发布名片可以从会员中心直接编辑并提交资料更新；审核期间继续展示原名片，管理员通过后自动更新广场，退回或拒绝时原名片保持不变。
9. 主动退出后旧名片保留。待审核、退回或拒绝的首次报名名片可修改后重新提交。

当前实现是兴趣名片与私密好友邀约，不包含公开评论、早晚定时匹配、自动群发问候、点赞或聊天系统。

## 生产配置与独立表

使用现有管理平台业务库 `SEATABLE_API_TOKEN` 与账号身份库读取配置，不复制分支测试凭据。
管理库 UUID：`076b49ed-6f04-4ea6-8799-1b9ad71dba88`。

| 早安晚安邀约表 | 19 | 邀约附言、三天反馈令牌摘要、邮件结果、成功结识反馈与历史通知状态 |

| 早安晚安黑名单表 | 12 | 本模块限制与解除记录 |

精确字段见 `lib/morning/schema.js`。采用分支兼容的文本字段，API 负责状态与输入验证。迁移不会写入业务行、复制测试数据、删除既有表或覆盖 Token。

```sh
node --env-file=.env scripts/apply-morning-schema.mjs
node --env-file=.env scripts/apply-morning-schema.mjs --apply --confirm=CREATE-NJU-RC-MORNING-SCHEMA
```

脚本验证生产地址和库 UUID，先保存私有元数据备份，按缺失表/字段追加，可中断后重跑；已有字段类型不符会拒绝执行。备份目录不能发布。
新增表复核后，设置 `WARMTH_MORNING_ENABLED=true` 并重启服务。默认关闭。功能开关开启且字段完整才接受业务请求。回退时关闭该开关，保留数据表。

运行时就绪检查同时核对列名与 `text` 列类型；列缺失、类型未知或类型不匹配时模块不可用，避免日期列截断邀约有效期等时间字段。既有额外列不受影响。

每日抽卡与心愿单使用 Node 内置 `node:sqlite`，无需新增 npm SQLite 包或在 SeaTable 建收藏表。启动时自动在 `PLATFORM_WRITE_STATE_DIR`（默认 `.write-state`）创建/补齐 `morning-plaza-daily.sqlite` 的 `morning_plaza_daily_snapshots` 和 `morning_plaza_favorites` 表。状态目录必须位于静态目录之外、可写且持久保留；备份和迁移须包含该数据库，在线备份使用 SQLite 备份机制或停服后复制，不能只复制正在使用 WAL 的主文件。代码发布不会清空收藏；丢弃状态目录会丢失收藏并重抽当天名片。

安装依赖须满足 `package.json` 的 Node `>=22.13.0` 要求，并使用 lockfile 执行 `npm ci --omit=dev --ignore-scripts --include=optional`。`sharp` 与 `@napi-rs/canvas` 依赖平台对应的可选二进制包，不可使用 `--omit=optional`；服务器无需安装 Playwright。依赖审计使用支持安全审计 API 的 npm 源。

邀约反馈使用服务端签名令牌，令牌和页面链接有效期为三天，数据库只保存令牌摘要。`MORNING_INVITE_SECRET` 留空时回退到 `PLATFORM_SESSION_SECRET`。

邀约成功反馈不再读取指导组名册或发送指导组通知。原「协调人通知状态」字段仅保留历史记录，无需迁移。

邮件中的唯一邀约处理链接使用配置的 `PUBLIC_BASE_URL`，不读取请求 Host 头。生产环境启用早安晚安且该变量缺失或为空时，使用正式站点 `https://njuredcross.cn`，不因缺少该变量阻止服务启动；开发环境未配置时使用本地服务地址。显式配置仍按原规则验证，非法值会拒绝启动，不会静默改为其他域名。使用其他生产域名时须显式设置 `PUBLIC_BASE_URL`；如已有配置指向 localhost 或旧域名，也需要更正，默认值不会覆盖显式配置。

## 权限、故障与边界

名片、邀约、修订和审核详情按账号或业务编号定位子表记录；广场读取本人名片与已发布名片，详情只读取本人和目标名片。条件查询、批量关联及兼容路径见 [内建查询说明](COMMUNITY_QUERIES.md)。

- 所有早安晚安业务接口需要登录；管理接口需要 community 权限，写入复用主线 CSRF、请求预算与限流。
- 通用表写入接口保护名片、名片修订、邀约、评论历史、标签和黑名单表，避免绕过业务审核。
- 发布、退出、重新报名、拉黑、发起邀约和反馈确认使用账号互斥；写入前重新验证双方状态。等待锁受请求截止时间约束。
- 此锁仅适用于当前单 Node 进程。多实例或绕过 API 直接修改 NJUTable 不受锁协调；扩容前需要共享锁/事务层。
- 全量读取达到截断上限时拒绝继续处理，不把部分数据当完整名单。现阶段未增加私有名片跨用户缓存。
- 数据库业务写入与审计、邮件不是分布式事务。严格审计写入失败可能在业务已保存后返回错误，应先刷新核对再重试。邮件沿用主线服务，不宣称可靠投递队列或恰好一次发送。

## 界面与验证

公众端采用主线品牌页头、字体、主题、分段校区选择和表单组件；同行广场按北京时间为每个账号每日随机抽取最多六张名片，并持久化当日顺序；当天重新打开仍展示同一组，次日优先抽取前一天未展示的名片。广场不提供翻页或搜索。桌面端固定为 2 行 3 列且卡片等高，平板与手机端按可用宽度降为 2 列和 1 列。名片详情复用桌面抽屉/移动端底部面板，保留键盘关闭与焦点管理；详情底部提供“发起好友邀约”，反馈链接以平台弹窗完成反馈。会员中心提供“编辑同行名片”，已发布名片的修改进入资料更新审核。后台在内建管理中分为生日祝福、早安晚安，后者提供统一名片审核、好友邀约统计、成员管理。

节点测试覆盖权限、隐私投影、每日快照和北京时间换日、审核状态、邀约令牌过期与篡改、反馈归属、成功统计、异步身份查找、失败重报名保留历史、退出竞争和迁移幂等。浏览器测试采用合成接口，覆盖 PC/移动端报名、详情、邀约、反馈、退出和后台视图，不使用生产 Token、真实邀约或真实邮件。
