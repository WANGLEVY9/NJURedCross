# 活动权限文件兼容修复

生产权限文件包含 `version / assignments / managedAccountIds`。回退代码仅识别
数组或 `rows`，因而把有效角色配置误报为 `workspace_roster_invalid`。

修复恢复已有角色规则的只读适配，不转换、不覆盖权限文件，不迁移业务表。
R01/R02/R03 分别保留南京综事、博爱、生命中心范围；R04 为苏州初审范围；
R05 保留明确配置的南京终审类别；R06 为苏州终审范围；R11 仍要求实时账号为
已验证且启用的超级管理员。初审和终审范围分别判断，不合并成全地区权限。
`排班专项` 作为既有 `排班类` 的读取别名，不改写持久化活动记录。

`managedAccountIds` 保留已迁移账号的撤权边界，撤销后不回退到旧组织身份。
旧 `rows` 记录中未被新配置覆盖的账号继续使用原地区权限。

部署沿用 `docs/OPERATIONS.md`，仅发布代码。不要删除或重建权限 JSON、
SQLite、初始化标记或其他私有状态。应用重启后重新读取原权限文件即可。
检查 Actions 部署回执、服务器发布清单和实际管理端详情/草稿请求。
若仍出现 503，按新的响应错误码排查，不能把代码检查通过视作线上修复完成。

回归测试 `tests/workspace-role-compatibility.test.mjs` 使用合成账号，验证
三种角色组合、文件内容不变、跨地区与跨中心拒绝、身份撤销和角色移除。
