## 活动与报名

网站普通活动使用志愿服务 Base 内的 `网站活动流程表`、`网站活动报名总表`、`网站活动签到表`、`网站服务时长明细表`、`网站志愿时长汇总表` 和 `网站个人主页表`。新报名总表参照原 `活动报名总表` 的活动类别、名称、日期、时段、岗位、学号、姓名、邮箱、校区、报名结果、志愿时长和录入状态，并添加网站账号、签到、请假与岗位来源关联。网站表采用文本存储状态机值，数值与身份在业务接口校验。

新表不复制测试记录或历史报名，不继承原总表的累计脚本。普通活动从旧业务表导入时，只建立活动配置来源，审批和发布仍在网站完成。

时长以新明细表为依据绝对重算，重复确认入账不重复累加。历史个人主页累计与网站新增明细分别保存；网站不会向旧累计脚本输入同一笔服务时长。审核完成的明细可以导出 Excel。历史累计与新增时长的合并规则需要在导入第二课堂前统一确认。

## 献血车

`市献血车汇总` 是实际日期、点位、时段和岗位状态的权威来源，每一行是一个独立名额。同一日期/点位/时段合并为一个日历班次，名额保留各行数量；停点仅扣除对应岗位，全部岗位停点才关闭班次。

`市献血车报名` 保留原入口及历史报名逻辑。此次检查显示新“周次滚动（每周·单表累积）”脚本配置直接追加 `市献血车汇总`；网站不再根据旧报名表的日期覆盖新汇总表，也不手工生成或发布献血车活动。

网站报名在新报名总表保存后，关联现有汇总岗位行，以 `网站报名ID`、`网站账号ID` 标识归属，写入姓名、学号、邮箱和 `待审核` 状态。名单确认写入 `成功`；拒绝或请假批准释放原岗位。既有人员占位、关联字段与待审核状态都计入名额；已关联网站记录不会重复计数。岗位同步失败可重试并按报名ID对账，禁止覆盖已可见的他人报名。

NJUTable没有跨客户端的原子条件更新接口：网站单进程写入串行化并在写前/写后复核；同一岗位不要在原表和网站同时人工修改。既有NJUTable自动化的跨入口竞争与邮件规则仍应在真实业务验收中检查。

日历每60秒自动刷新，保留所选周次、日期与点位，也提供手动刷新。PC采用七列，手机采用日期条与当日班次。此刷新周期是网站同步周期，不表示NJUTable周次生成时间。核查到的旧模板规则为周四09:00，但仍指向旧模板表；新滚动脚本的实际定时绑定尚未确认，因此页面不展示未经确认的每周生成倒计时。

## 环境配置与迁移

配置 `PLATFORM_WORKFLOW_MODE=production`、正式志愿 Base UUID、`SEATABLE_BLOOD_SOURCE_TABLE=市献血车汇总`、`SEATABLE_VOLUNTEER_NOTICE_TABLE=活动报名通知`。`scripts/configure-production.mjs` 默认预览，`--apply` 仅创建缺失网站表及补充岗位关联字段，校验Base UUID和已有字段类型，不复制任何历史行。

身份登录库独立保留，密码、账号ID与角色不迁出。资料映射按学号和真实姓名精确重新绑定；不匹配的账号保留人工核验状态。迁移前备份身份映射及服务器配置，正式个人主页不被测试副本的缓存资料覆盖。

### 献血车空位提醒与周次入口（2026-10-06）

献血车在活动广场按周聚合，周入口连接七列日历；手机采用日期条及当天班次。正式报名占用原有排班名额，待审核也占名额，公开接口仅提供数量与当前账号报名，不返回其他参与者身份。管理员在活动中心的名额详情中查看来源岗位及精确匹配的志愿者主页资料；源记录尚未填写的资料不会推断生成。

心愿清单存储于志愿服务 Base 的 `网站献血车心愿清单`。仅已验证账号可订阅未开始的满额班次，可取消订阅。服务每分钟读取正式源表检测空位（包括 NJUTable 直接释放）；SMTP 成功后记为已提醒，失败五分钟后重试。同一订阅使用稳定的邮件幂等键，发送记录及状态均持久化。提醒不预留名额。SMTP 已送达但记录写入失败的极端中断仍可能重复提醒；不承诺跨系统事务中的恰好一次投递。

服务器 Node 22 网络自动选择在双栈 NJUTable 上出现连接超时，curl 可达。生产 systemd drop-in `/etc/systemd/system/njuredcross.service.d/network.conf` 使用 `NODE_OPTIONS="--no-network-family-autoselection --dns-result-order=ipv4first"` 后正式 API 恢复。此项是服务器启动配置，Git 推送不会自动应用。
