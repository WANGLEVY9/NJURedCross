# 物资借用资格接口

2026-10-11 用户确认：只允许“个人主页（编辑版）”的“部门”为主席团 & 指导组、综事中心主任团、生命中心主任团、博爱中心主任团、工作组主任团的账号申请借用。其余部门、空值、未知值均禁止。代码使用真实选项名称“主席团 & 指导组”“综事中心主任团”，对应讨论中的第一、第二类。

## 用户端对接

本地预览提供 `GET /api/public/materials/borrow-eligibility`，须登录，无请求参数。响应只包含当前账号的资格，不返回成员名单、学号或联系方式：

```json
{
  "ok": true,
  "local": true,
  "eligible": true,
  "status": "eligible",
  "department": "工作组主任团",
  "message": "已具备物资借用资格。"
}
```

`status` 有四种：`eligible` 允许申请；`not-internal` 部门不符合；`unverified` 尚无可靠个人主页匹配；`unavailable` 只读来源读取失败。后三种均为 `eligible: false`。来源未确认时不返回部门值。未登录返回 401。

2026-10-12 同步用户端提交后，借用页已接入此接口，替代该页原有 `memberCode` 判断，并提供重新核验入口。未核验、非内部部门或来源故障均不显示申请表；资格查询失败不回退到会员码。提交申请仍调用已有 `/api/public/materials/requests`，服务端再次核验资格；无资格返回 403，来源故障返回 503。马甲的自动审批在资格校验之后进行。会员码、管理员身份、申请中的 `department` 或 `studentId` 不能使不合格账号获得资格。

## 服务端身份与只读来源

`createLocalMaterialsPortal` 接受服务端注入的 `membershipFor(actor)`。缺少此核验器默认禁止申请。`createMaterialMembershipReader` 提供 GET-only 实现，限定志愿服务试验板及个人主页表；使用认证层提供的 `actor.id`、已验证邮箱标记 `emailVerified` 和 `studentId` 精确匹配。不会使用申请体里的学号查找资格，不按姓名或 `memberCode` 猜测。重复学号资料须人工核验。

账号中的 `department` 目前表示“院系”，不可代替个人主页的“部门”。本地合成身份使用独立的 `redCrossDepartment` 测试字段，并显式标为模拟会话。真实 API 副本已连接只读核验器，但当前会话仍为模拟身份，缺少已验证真实学号时显示未核验并阻止申请；正式登录账号的接入继续由认证接口负责，不读取账号存储库来伪造绑定。

只读适配器按完整分页检查，容量上限 10000 行，重复行号、无效分页或缺少字段时停止核验。[SeaTable GET 记录接口](https://api.seatable.com/reference/listrows) 返回整行字段；适配器只保留本账号的部门结果，不保存或输出人员行数据。每次申请重新核验，既有申请回执不能绕过变更后的资格。

申请和库存仍仅写隔离内存；原借用人的归还只校验登录与原单归属，部门变更不解除归还责任。采购入库、报销和审核权限沿用各自规则，借用白名单不扩展到这些业务。邮件暂缓。
