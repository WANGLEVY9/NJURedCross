# 前端设计系统与交互约定

沿用既有前端设计说明，修改时核对实际组件与样式。运行和模块组织见 [前端 README](../public/README.md)；浏览器交互效果仍需单独 QA。当前首页、活动广场、日历与共享背景的源码设计摘录见 [DESIGN.md](../DESIGN.md)，扩展动效、断点和组件预览见 [.impeccable/design.json](../.impeccable/design.json)。

## 前端架构

无构建工具、无外部运行时依赖，直接以原生 ES Module 提供服务；服务端 CSP 为 `script-src 'self'; style-src 'self'`，因此代码中**不存在内联样式与内联脚本**，所有动态样式都通过 CSSOM（`style.setProperty`）或 SVG 表现属性写入。

```text
public/
  index.html                应用外壳（环境层、overlay 根、toast 根）
  assets/                   品牌标记与噪点纹理
  styles/
    tokens.css              共享设计令牌（双表面：portal / console）
    themes.css              既有主题与偏好样式
    calendar.css            献血车日历的局部视觉与响应式覆盖
    atmosphere.css          共享品牌光场与减少动态效果适配
    discovery-art.css       首页、活动广场与共享页脚的通透表面覆盖
    base.css                Reset、字体层级原语、环境视觉层
    components.css          共享组件层
    portal.css              公众门户布局
    admin.css               控制台工作区布局
  app/
    main.js                 引导、路由表、会话守卫、渲染管线
    core/                   dom / router / api / store / motion / format / toast / keys
    ui/                     primitives · overlay · palette · chart · table
    portal/                 公众端外壳与页面
    console/                管理端外壳、共享区域工具与页面
```

### 设计系统要点

- **令牌先行**：共享颜色、字体、间距（4px 基数）、圆角、层级与动效时长以 `tokens.css` 为基础，`themes.css` 提供主题覆盖；日历文字、班次基础色、阴影及局部排版位于 `calendar.css`，环境光位于 `atmosphere.css`，首页和活动广场局部文字、阴影及排版位于 `discovery-art.css`。公众端与管理端沿用各自主题偏好和同名语义变量。
- **克制的主色**：主色承担关键操作、Focus、Active、数据高亮及随主题变化的背景光场；页面结构主要依靠排版、留白、分隔线与表面层次建立。
- **状态三重表达**：所有状态同时使用颜色、文字与图标（必要时加脉冲动效），不依赖颜色单独传达信息。
- **Card 不是默认容器**：只有具备独立语义、状态与交互时才使用面板；其余用 `wsregion` / `section-head` / 分隔线 / 表面层建立结构。
- **完整状态覆盖**：每个数据区域都实现 default / loading（骨架屏）/ empty（含主操作）/ error（原因 + 重试 + 技术细节）。

### 交互与动效

- **命令面板**：`⌘K` / `Ctrl K`（`/` 亦可）打开，支持模糊搜索、分组、最近使用与键盘导航；命令源由当前外壳注册，因此始终与当前界面能力一致。
- **快捷键**：`⌘K` 搜索 · `⌘I` 通知中心 · `⌘B` 折叠导航 · `⌘⇧D` 切换信息密度 · `Esc` 关闭当前面板／Inspector · `↑↓` 列表导航 · `Enter` 确认。快捷键可枚举，并在 Tooltip 与系统设置中展示。
- **Inspector 优先**：在列表中选中对象时右侧滑出详情，而不是跳转页面；窄屏自动改为覆盖式面板。
- **Drawer / Sheet / Modal 分工**：上下文创建与编辑用抽屉（窄屏自动降级为底部 Sheet），仅不可逆确认使用模态（支持输入短语二次确认）。
- **上下文菜单**：列表行支持右键菜单，动作按对象状态启用或禁用。
- **Motion System**：`transform` / `opacity` 驱动，共享时长为 90–620ms；日历筛选重绘为 220ms，全局背景无运动；包含页面淡入位移、FLIP 布局过渡（筛选与排序）、共享元素扩展（活动卡片 → 详情）、Spring 抽屉与开关、磁吸主按钮、面板 Spotlight 跟随、Hero 视差与数字滚动计数。全部遵循 `prefers-reduced-motion`。
- **写入前预览**：入库/出库/归还/盘点会先显示 `18 → 15` 形式的库存变化与阈值影响；报名会先说明「直接确认」或「候补第 N 位」。
- **结果凭证**：写入成功后返回业务编号、时间、操作摘要与后续动作；报名与代报名额外返回可下载的签到二维码。

### 数据可视化

图表全部为自研 SVG，不使用图表库默认皮肤：坐标轴与网格刻意弱化，数据承担视觉重量，支持十字准线、交互 Tooltip、图例开关与入场动画。趋势曲线只使用真实事件（活动报名/签到/取消、物资出入库流水）按 Asia/Shanghai 逐日聚合；没有事件时显示空状态而不是伪造曲线。

## 首页、活动广场、日历与背景的实现及验证边界

- 1101px 起预约工作区最大宽度为 1480px，日历头部以 230px 月份/周导航列与弹性筛选列并排；共享门户页头高 72px，导航项高 40px，当前页保留主题浅底、文字和下划线。日历桌面保持七列周视图，700px 及以下仅展示选中日期的班次；摘要始终统计整周筛选结果。点位与“仅看有名额”可组合，无结果时区分无排班和已满，重置保留当前周。筛选自动选择有匹配班次的日期，保留日期焦点与传入状态。
- 桌面提供“舒展/紧凑”密度：班次最小高度分别为 164px / 125px，选择保存在传入的日历状态对象中；700px 及以下单日布局不受桌面密度影响，不声明跨会话持久化。日期左右方向键在当前周内移动，Home/End 选择周首/周末，到边界停止；选中状态与焦点同步。
- 选择班次后立即滚动并聚焦详情容器；“返回日历”恢复选中班次焦点，若该班次不存在或不可见则恢复选中日期焦点。该流程不改变报名资格、名额计算和提交接口。
- 全平台背景由 `atmosphere.css` 按当前页面根类分配：主页暖纸、活动低噪、日历/会员中性工作底色、宣传象牙、内建暖纸。移除全屏光场、巨幅曲面、通用十字与指针视差；正式徽标与主题操作色保留。首页深蓝主视觉、白色服务章节和砂色页脚归 `discovery-art.css`。强制颜色模式使用 Canvas。
- 首页与活动广场内容最大宽度为 1480px。首页桌面双列主视觉、实色服务面板与真实统计延续日历的浅色表面；760px 及以下主视觉单列，服务面板在所有宽度均无模糊，五个广场入口按宽度收至三列、两列、单列。正式标识为 72px，480px 及以下为 56px。减少透明度偏好使服务面板、统计条和广场标题变为纯白。
- 活动广场展示搜索、状态、分类和校区的已选条件，支持单项清除与全部重置并同步 URL。清除状态或分类后聚焦对应分段，清除搜索、校区或重置全部后聚焦搜索框；校区按钮重绘保留焦点。结果通过 polite、atomic 状态区域宣告，献血聚合与班次计数保留。键盘输入跳过列表 FLIP，指针输入恢复；不改变活动资格、报名或数据接口。
- `tests/browser/discovery-art.spec.mjs` 提供合成数据下的首页、活动广场、共享背景与筛选回归；具体运行结果以当前测试记录为准。设计检测器输出属于待核对的建议，不是部署或真实业务验收证据。
- 班次保留状态文字、图标、剩余/总名额和选中轮廓；主题色不替代报名状态语义。
- `tests/browser/calendar-design.spec.mjs` 覆盖合成数据下的筛选、响应式、桌面密度、日期键盘导航、详情返回焦点与减少动态效果；既有浏览器套件和 Node 测试仍需随改动运行。截图属于对应测试环境的视觉证据，不代表生产数据、报名容量或完整无障碍审计。
- 发布完成须按 [OPERATIONS.md](OPERATIONS.md) 核对 Actions、服务器发布清单和线上页面；本设计文档不声明部署已完成。
