# 活动项目关系完整性

网站活动与活动项目继续使用现有 `报名页配置` 中的
`ordinary.groupId`、`positionPlan.groupId` 和 `parentActivityId` 关联。活动名称
不参与归组；同一名称可以对应不同项目，只有相同活动组 ID 才会聚合。

配置写入已有 10000 字符上限、私有编辑回执和写后回读。配置超过安全长度或读取时
无法解析为 JSON 对象，活动列表标记配置异常，编辑与发布停止，已有报名记录保留。

## 关系检查

管理员可通过 `GET /api/volunteer/workflow/relationship-integrity` 读取当前关系检查
结果。响应只包含活动标识、问题代码和汇总，不包含报名人资料。活动读取也会把关系
异常标记到对应项目；管理页停止编辑和发布。完整性 API 按当前账号的权威活动范围
过滤活动和项目组，只返回该范围内的标识与问题代码。

检查覆盖重复活动 ID、重复项目行、缺少项目记录、岗位缺少活动组和父子活动不一致。
已归档活动不参与当前阻断判断。

## 配置损坏的活动

配置损坏但仍有有效报名的活动应先从完整备份或私有编辑回执核对恢复。没有报名、
签到、时长或当前岗位关联的历史重复记录，可以在 NJUTable 中软归档：

```text
归档前状态 = 当前状态
状态 = 已归档
```

保持原行、原 `活动ID` 和原配置不变。不要用补全括号、清空 JSON 或新建同名活动来
绕过配置异常。
