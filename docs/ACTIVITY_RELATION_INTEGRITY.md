# 活动项目关系完整性

网站活动与活动项目的关系保存在 `网站活动流程表` 的 `活动组ID` 和
`父活动ID` 原生字段中。`活动组ID` 标识完整项目，`父活动ID` 只在岗位活动中填写。
活动列表、岗位投影和公开活动读取优先使用这两个字段；迁移前的历史记录继续从
`报名页配置.ordinary.groupId`、`positionPlan.groupId` 和 `parentActivityId`
兼容读取。

新多岗位项目在提交时生成确定性的 `PROJECT-<活动ID>` 活动组 ID。发布生成岗位时，
每个岗位同时写入相同的 `活动组ID` 和所属父活动 ID。活动配置损坏时，只要原生关系
字段完整，项目仍可被正确归组；配置错误单独阻止编辑和发布，不会把记录静默拆成
第二个项目。

关系检查以活动 ID、活动组 ID 和父活动 ID 为准，不使用活动名称。合法的同名活动
可以并存，但同一活动组必须只有一条项目记录，岗位必须指向存在且活动组一致的父活动。
缺少任一关系的活动应停止发布和写入，并由管理员从完整备份核对。

`网站活动流程表` 新增的两列由工作流 Schema 预览/应用工具维护。历史记录回填只读取
活动组与活动配置生成计划，默认预演；执行前必须备份业务行和私有状态，并核对每个
活动组、父活动及岗位的唯一关系。
