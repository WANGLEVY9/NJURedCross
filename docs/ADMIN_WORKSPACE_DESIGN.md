## 视觉规格

不另建主题。复用 console 的 `--bg-base`、`--bg-sunken`、`--surface`、`--border`、`--accent` 与状态令牌：中性工作区、弱分界、红色当前对象/主操作、文本状态徽章。颜色取值继续由 tokens/themes 管理。

- 字体：NJU Sans；页面标题 24px，对象标题 22px，正文 14px，目录 14px，辅助文字 12–13px，表格 13px。
- 桌面目录 292px；主区 `minmax(0,1fr)`，目录与详情分别滚动；1100px 以下恢复页面滚动，800px 以下上下排列。
- 桌面控件约 36px；班次用紧凑分隔行，不再为每个班次建立独立白卡。
- 页面唯一创建主入口；业务主操作沿用真实状态和权限分支。表格仍用原有选择、排序和错误反馈。
- 键盘可展开/选择；当前对象具有 `aria-pressed`，展开有 `aria-expanded`。目录不是伪造的 ARIA tree，不承诺未实现的树键盘模型。

## 状态与风险边界

保留 `event`、`mode`、`area`、`tab`、`q`；补齐 `category`，新增 `scope=session` 与 `explorer=hidden/visible`。历史不带 scope 的项目链接仍进入项目层。数据关系仍采用现有 `activity-projects.js`：普通活动明确 groupId，献血车按现有来源/月度规则，不变更后端聚合或数据库。

筛选父项时检查子班次状态，避免代表行报名中掩盖待审核子项。返回父项目与查看子班次不更改任何报名 ID。折叠目录不卸载业务表格，避免丢失未提交输入。风险操作继续走原有 API 和确认。

本轮不迁移表结构、不修改 NJUTable Token、不执行真实审批/签到/时长录入。新建活动表单的完整分步重构、发布编辑器统一以及深层审核表格改造属于后续 P02–P04，不在本轮宣称完成。
