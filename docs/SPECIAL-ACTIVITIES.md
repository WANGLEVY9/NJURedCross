# 排班专项与长期登记

## 使用入口

- 校医院体检、校医院疫苗接种：在原有活动管理页面新建活动，选择“排班专项”。活动名称提供这两个建议，也可以填写其他名称。草稿保存、预览、审批和发布沿用原流程。
- 草稿填写日期范围后，在小日历中勾选实际服务日；支持跨月、跨年。按地点添加时段、名额和时长，不再要求填写岗位。只有选中的日期生成班次，按地点、时间排列。
- 发布后在原工作区选择周次，使用“报名处理 / 签到与初审 / 终审与导出”。保留单人、整行、整列选择及批量操作。更多操作中的“项目总表”可查看同一项目全部周次的记录。
- 超管可通过活动管理顶部“启用长期登记项目”分别启用省血液献血车、成分献血。重复启用打开原项目，不复制、不重新开放已结束项目。省血液启用时设置每日名额。
- 两个长期项目直接进入“进行中”，公众端显示“可登记”，不填写虚构的结束日期；通过“结束登记”手动停止新增，历史记录仍可查看。

## 登记与审核

省血液献血车只需选择服务日期；姓名、学号、部门、邮箱和校区从已验证账号带入。没有报名时段或岗位输入。服务登记经管理员确认后，可以上传签到凭证，负责人核实实际到场并填写实际服务时长，再由具有终审权限的人员审核。每天名额在服务端串行校验，重复请求不会新增记录。

成分献血在实际完成后登记：实际献血日期、实际时长（不含交通，最多一位小数）、献血量数字、献血证截图或照片。它不走预约、候补或现场签到流程。管理端核验献血证后只生成待终审时长，不直接批准、入账。凭证通过已有私有照片服务保存和鉴权读取，不生成公开图片地址。

排班班次在开始时停止报名，或按草稿设置提前截止。服务结束不会立即关闭凭证上传；没有线上凭证时，负责人必须明确确认实际到场并填写说明才能初审。初审后的记录保留为“审核中”；终审仍须等本班次结束，并遵守分管权限及核对人不能自行终审的规则。

整周所有班次结束、报名与请假处理完成、时长审核完成后，才可完整导出并归档。分批导出不会归档。已归档周次从当前可选周移出，在历史活动中保留预览和下载；其他周次继续运行。

## 底表与发布边界

- 沿用现有网站活动、报名、签到和服务时长明细表以及原生字段类型。登记元数据使用报名表已有的“备注2”长文本字段；不增加一套替代业务表。
- 时长仍通过既有两张汇总表入账；个人主页由 NJUTable 自动化维护，网站读取显示。
- 新逻辑由明确的版本与专项类型标记启用，不根据活动名称推断。既有普通活动、市献血车和已有排班记录不会自动转换。
- 加载页面、启动服务及部署代码不会自动创建长期项目，也不执行清表、重置报名、导入模拟数据或覆盖运行状态。启用长期项目是管理员显式操作。
- 超出既有配置体积或班次数量上限时拒绝发布并提示调整，不截断日期或覆盖已有班次。修改已发布活动信息仍沿用超管入口，不重新生成已有报名。

## 本地合成预览

在项目目录的 PowerShell 中运行：

```powershell
$env:PREVIEW_SPECIAL_ACTIVITIES='1'
$env:PORT='3121'
npm run preview:workflow
```

打开 `http://127.0.0.1:3121/console/events`。此入口只使用隔离的内存数据，不读取 `.env`，不连接生产底表或 SMTP。预览服务重启后合成记录清空；生产状态不会因此改变。样例使用固定的合成服务日期，用于检查已结束班次、跨周记录和无签到凭证的初审。

## 验证范围

覆盖明确服务日期、跨月跨年、独立报名截止、跨周批量边界、负责人到场说明、初审与终审分离、整周归档及历史下载、下一周仍可报名、每日限额并发与请求幂等、原生字段写入、凭证与登记一致性、分管权限及权限撤回。桌面与手机浏览器检查紧凑看板、批量初审、项目总表、登记表单和十二月日历。

部署是否完成，以 GitHub Actions 和运行发布清单为准；源码推送成功不等于已经上线。
