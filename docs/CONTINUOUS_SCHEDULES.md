# 管理端持续排班与分批处理

本功能只对现有自动排班适配器生成的活动生效（服务端 `source.kind=generated_blood`）。不根据活动名称推断类型，不把普通活动或手工多岗位活动自动改成并行模式。普通活动继续使用原有报名、签到、整表提交及审核流程。

## 进入与维护

- 管理端活动管理的“管理工具 → 献血车排班”可查看底表、模板、当前班次数和占位关联列是否就绪。
- 进入自动排班项目后，“排班来源与模板”打开相同只读入口。模板只展示序号、点位和活动时间，不返回报名人、邮箱、学号等资料。
- 沿用模板表 → NJUTable 自动化 → 实际岗位底表 → 平台适配器。不要用“新建活动”或“来源活动纳入”复制生成另一套活动。
- 本轮按要求不修改生产表名配置、不扩展点位与时间格式，也不改底表自动化规则。实际源表仍由现有服务配置决定，源码中的默认名称不表示已验证生产连接。

名额继续以底表每行一个位置为准，追加空余位置或下一日/下一周的班次后，刷新读取。不得删除已被报名占用的底表行、改写已有班次的日期/地点/时段，或在其他入口覆盖网站占位。减少容量应只减少未占用名额，或使用已有停点规则；名额减少不自动取消已接受的报名。新报名仍受容量与具体班次开始时间约束。

正式报名占位要求源表已有 `网站报名ID`、`网站账号ID` 两个文本列；这是既有适配器的关联字段，不是新的活动模型。入口会报告缺失列，正式报名会在新增网站报名行之前停止。由生产管理员核对配置并维护列，本功能不自动增列或修改生产表。

## 并行操作

自动排班项目提供三个可随时切换的工作入口：

1. 报名审核与通知：沿用原有逐条/批量确认、请假审批和通知投递。
2. 签到与分批录入：只录入本次选择的人员，其他记录保持原状；保留照片、到场核验及未批准报名不能签到的限制。
3. 时长审核与导出：逐批审核已录入记录，导出仍只包含审核通过且服务时长大于零的记录。不要求先关闭整个排班月份或等待所有人处理完。

各项操作共享已有写队列，但不会共用一个整月提交锁。已审核通过的个人明细保持锁定，不能借并行入口重写。自动班次按时钟显示已结束后，原有待审核报名仍可确认和通知；不会重新开放新报名，也不放宽参与者上传签到照片的时段要求。未保存的编辑在切换工作入口/刷新前仍须处理。

## 时长证据与兼容

新录入的自动排班时长使用 `v4` 证据摘要：排除容量这一个动态字段，保留账号、学号、姓名、班次时间、地点、核验记录、照片、时长规则等证据。后续增减空余名额不会仅因容量变化使这类明细失效。修改证据或篡改核定明细仍会阻止审核与入账。

普通活动仍用原有摘要。历史 `v2/v3` 和未带版本的明细继续按原规则严格校验，不能在未核对证据的情况下批量升级或跳过校验。若历史明细曾因容量调整失效，需要独立核验处理；本轮不会自动修改这些历史数据。

## 发布验收

隔离测试覆盖新增名额/新班次、待审核报名与部分时长并存、分批审核导出、重复入账保护、名单及证据篡改、源表关联列缺失、模板只读和普通活动不受影响。

上线前仍须由有权限的管理员只读确认实际源表、模板自动化、占位列以及通知发送配置。代码验证不能替代生产配置验收。不要为了验证往真实表写合成人员或模拟报名。
