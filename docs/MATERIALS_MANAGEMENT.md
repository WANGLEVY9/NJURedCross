# 物资管理：独立修复与本地验证

这轮开发针对管理端 `/console/materials`，基于 `be8e7c1` 建立本地分支。只处理现有单资产流程和管理员使用的功能，不更改公众物资申请表、账号绑定、取消/改期、审批预约库存或多品类申请明细协议。这些共享需求保留到与借用模块负责人对齐后再做。

## 功能范围

- 扫码、台账和库存操作共用“现有基线 + 新流水净变化”的库存口径。
- 对原始数量校验有限整数，不四舍五入；归还可仅登记损耗，但损耗不会增加库存。
- 根据可验证的实际出库、累计归还和损耗判断剩余责任，拒绝超额归还、错误资产和重复出库。
- 普通核查备注不代表损坏；分次归还展示剩余件数，真实损耗保留异常提醒。
- 已记录流水但申请更新失败时保留恢复信息，恢复只补申请状态，不重复产生库存变化。新操作在未同步状态下被拦截。
- 申请及流水更新检查失败回执并读回确认；未确认落盘时不会误报同步成功。同期核查与同步共用流水锁，保留核查说明。
- 编辑已有物资名称、单位、位置和阈值；直接修改基线数量仍被禁止，库存变化走入库、盘点、报损等操作。
- 保留管理员直接领用、消耗出库，去向必填；借用归还必须关联原申请和出库资产。
- 完整流水按关键词、资产、操作、操作人和日期筛选、分页。CSV 导出明确为当前页，带 UTF-8 BOM 并处理电子表格公式前缀。
- 对异常流水记录管理员核查说明，或重试待同步申请；核查说明不能替代实物归还或损耗结算。

这一轮不新建底表字段或单选状态，不自动迁移历史记录。已有单选/数字等资料列按元数据契约校验；不支持直接编辑的列不得通过字符串强行写入。历史缺少可验证出库关联的申请可以继续查看，自动结算需先完成来源核查。新增物资和停用功能留待真实底表契约确认后补充。

## 本地启动

需要 Node.js 22.13+。安装依赖和验证：

```powershell
npm ci --ignore-scripts
npm run verify
npm run preview:materials
```

打开 `http://127.0.0.1:3122/console/materials`。预览仅监听本机，使用合成库存、申请、流水及模拟会话；不读取 `.env`，不连接 SeaTable/SMTP，不发送邮件，重启后重置内存数据。可通过 `PORT` 改端口。它能验证本地行为和页面，不能证明真实角色、权限、上传和数据源兼容性已验收。

## 管理接口

所有正式物资接口沿用管理角色、`materials` 范围和写请求 CSRF 检查。

| 接口 | 用途 |
| --- | --- |
| `GET /api/materials/overview` | 台账、待办、库存与申请进度、最近流水 |
| `GET /api/materials/scan?code=...` | 按资产编码定位，使用与台账相同的库存计算 |
| `GET /api/materials/schema` | 物资可编辑字段的类型和允许选项 |
| `PATCH /api/materials/inventory/:id` | 已有物资资料和阈值维护 |
| `GET /api/materials/flows` | 完整流水筛选和分页 |
| `POST /api/materials/flows/:id/retry-sync` | 只恢复已持久化操作的申请状态 |
| `PATCH /api/materials/flows/:id/review` | 保存异常核查说明 |

资料维护字段为 `name`、`unit`、`center`、`cabinet`、`level`、`threshold`、`thresholdEnabled`。不接受数量、资产 ID 或任意表名。流程状态仍使用原表允许值，新增进度为接口派生字段，不向底表添加状态选项。

流程和恢复通过注入的数据客户端测试，不在模块导入时启动生产服务。恢复信息存放在现有流水说明列中，业务响应仅返回受控投影，不向页面展示恢复元数据和上游原始错误。库存仍由基线与流水计算，资料保存不能改写历史库存基线。

## 验证和上线边界

专项回归入口为 `npm run test:materials`；完整提交门槛仍是 `npm run verify`。专项应覆盖数量拒绝、累计结清、错资产/重复操作、部分成功恢复、资料类型校验、分页、CSV 和本地 HTTP/CSRF 路径。

正式部署前在独立测试 Base 验证：

- 既有字段、图片列和单选值与目标 SeaTable 实际结构一致。
- 真实管理员权限和成员拒绝路径正确。
- 上传失败、写入超时及跨表部分成功后可安全恢复。
- 历史无流水申请的人工核对方式，以及底表“现有数量”是否仍被其他脚本更新。
- 归还、损耗和异常处置规则与借用模块负责人一致。

当前进程内队列不提供多实例事务保证；发布前须确认单写入者/单实例边界。合成预览和本地回归不会改变生产开关，也不证明邮件、真实相机或历史迁移完成。代码合并与上线部署分别处理。
