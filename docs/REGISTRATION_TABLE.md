# 网站活动报名总表：原生类型与读写契约

一行对应一位志愿者的一次班次报名；活动、班次及报名不是同一实体。旧 `活动报名总表` 继续保留，不复制其历史报名，不修改其列或关联。迁移工具与应用发布独立。

## 原生字段

| 用途 | 字段 | NJUTable 类型 |
| --- | --- | --- |
| 分类与筛选 | 活动类别、地区、院系、校区、部门、性别、年级、急救证 | single-select |
| 班次与流程 | 报名时段、岗位、报名状态、录入状态、请假状态、报名类型、岗位同步状态、关联状态 | single-select |
| 日期 | 报名日期 | date，YYYY-MM-DD |
| 业务时间 | 开始时间、结束时间、创建时间、请假申请时间、签到提交时间、资料补录时间 | date，YYYY-MM-DD HH:mm；原精确值另存 |
| 成功标记 | 是否报名成功 | checkbox，不默认录取 |
| 数值 | 志愿时长、献血量 | number，分别两位小数 / 整数；空值不等于零 |
| 说明 | 备注、备注2、注意事项、请假原因、处理说明 | long-text |
| 网站内部导航 | 活动名称2、签到表、时长明细、个人主页 | link，关联网站自己的流程/签到/时长/镜像资料表 |
| 附件与通知 | 图片、邀请链接、QQ群号 | image / url / text |
| 自动记录 | 序号、修改时间、修改者、系统创建时间 | auto-number / mtime / last-modifier / ctime |

保留原有报名ID、活动ID、账号ID、学号等 text 标识，不转换成数字。电话与 QQ 保持文本，避免前导零丢失。`活动类型` 保留“志愿服务”“献血车志愿服务”等服务类型，不能与 `活动类别` 混用。

类别字典包含旧表六项及 Owner 确认新增的“献血车专项”，另有“未分类”。献血车使用“献血车专项”；献血周使用“主席团”。地区仅南京地区、苏州地区；前端另提供“全部”。院系、岗位和报名时段继承旧表有效选项，并补入当前活动值；新活动的新岗位/时段在保存时补入选项。旧表异常数字、不完整时段及失效级联不复制。

## 资料与关联边界

性别、电话、QQ、院系等采用报名资料快照，不直接照搬旧表 lookup。旧 lookup 依赖旧主页/通知/反馈关系，复制其 link ID 会关联错误数据。迁移只对学号和姓名唯一精确匹配的旧主页读取补充字段；不覆盖原报名姓名、邮箱、院系、校区，不改变账号角色。`资料来源`、`资料补录时间` 记录补录依据。管理端优先呈现本次报名快照，未填写字段可使用受限目录补充。

网站 `个人主页` 关联的是时长镜像，只有已有匹配镜像时关联；不创建虚假的零时长主页。献血车班次来自排班表动态生成，并无网站流程实体行，不伪造活动行来填关联；源岗位仍由 `岗位源行ID` 绑定。`关联状态` 表示已有适用网站关系是否核对，不代表每个 link 都非空。

图片是可选底表附件字段，不替代私有签到照片证据。通知/反馈旧表关联不搬入网站表；QQ群号、邀请链接、注意事项保留可填写字段，暂不自动推导旧通知关系。没有承诺从图片列自动建立公开相册。

NJUTable 日期读回可能截断秒数。历史创建/请假/签到精确值分别存入 `创建时间原值`、`请假申请时间原值`、`签到提交时间原值`，正常读写自动维护；不要手工修改这些技术列。`系统创建时间` 是平台自动时间，原 `创建时间` 保留历史业务时间。

## 管理端与底表操作

- 管理端创建活动：填写活动类别、地区、时段/岗位 → 网站流程表保存 → 报名时按实时活动配置写入原生报名字段。普通多班次项目从项目表继承组织类别/地区；审批业务摘要不因单独分类更新而失效。
- 底表修改报名备注、联系方式、资质等，在管理端刷新后读取并呈现；不反向改账号资料。类别/地区修改影响该报名的统计，不自动改整个活动。
- 整个活动的类别/地区在 `网站活动流程表` 的 `组织类别`/`活动地区` 设置；普通多班次项目优先用 `网站普通活动项目表` 对应字段。公共活动筛选读取活动配置，不从某条报名猜测。
- 日期、地点、容量等已审批的关键业务条件不能单独改后绕过审批。报名状态、成功复选框、签到核验与时长审批也不是彼此可替代的单元格；操作应保持一致，不一致时正式时长核验拒绝入账。
- 报名表的 `志愿时长` 可以用于底表合计，但手工修改不会绕过审核直接改变正式时长明细和会员累计。会员显示“报名表时长”时注明正式时长以审核入账为准。献血周仍是时长规则待确定，不自动计两小时。
- 新增网站内部 link 在报名、签到、时长核验/入账时维护。关联故障标记待核对，不把已经保存的报名误报为失败。
- 刷新读取受短期缓存约束，并非推送同步。一般报名表读取缓存为 5 秒，活动公开快照有有限有效期；底表变更在刷新与缓存重新验证后体现。

## 独立迁移工具

先完成应用部署，再在服务器受控工具目录使用生产 `.env`，不可把 `.env` 复制到 Git。

```bash
node --env-file=/opt/njuredcross/.env scripts/migrate-registration-types.mjs --classify-current-programmes
```

默认只读，输出类型、选项、格式、行数与 schema/原行摘要，不输出个人报名值。`--classify-current-programmes` 仅执行 Owner 已确认的现有献血周分类，要求项目唯一且有 16 个班次；献血车分类由动态班次适配器提供。

应用阶段要求 `--apply --confirm=MIGRATE-WEBSITE-REGISTRATIONS --expect-digest=<只读预览摘要> --backup-dir=<仓库之外的绝对路径新目录>`。目录须不存在，父目录由维护人先建立。短暂停止网站写入，重新预览再应用；禁止同时在 NJUTable 手工编辑。工具保存私有原 metadata、全部原报名、相关网站行及目标值，目录 0700、备份 0600；转换后逐个值验证，再恢复服务。

转换可能清空单元格，因此不是只改 schema：工具按验证过的目标值恢复原报名，保留行 ID、空值与精确时间。失败尝试恢复原类型与原报名值；已加的列保留以便对账。备份不得公开；回滚失败时停止推进，依备份修复后验证，不能仅重启服务宣称成功。

`scripts/apply-workflow-schema.mjs` 仍可初始化旧 text 核心表，同时接受迁移后的原生列；原生升级使用本迁移工具，不在运行时偷偷改类型。测试工具 `scripts/probe-registration-types.mjs --confirm=ISOLATED-SCHEMA-PROBE` 仅接受测试 Base UUID，创建独立合成表并清理，不写真实业务表。

时长明细表缺失的八个核验字段由迁移补齐；不写时长业务行、不触发入账、不发送邮件。代码回滚不自动撤销数据库迁移，必须单独核验兼容与数据备份。
