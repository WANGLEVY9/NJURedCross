# 活动报名工作区

本页记录活动班次、报名确认、参与记录和心愿清单的组件约定；服务端仍是资格、容量及业务结果的权威来源。

## 审计与改进

| 原问题 | 当前实现 |
| --- | --- |
| 日期、地点、时间等权排列 | 日期导航 → 场馆分组 → 时段与真实状态；选中标记不取代已报名状态 |
| 摘要四字段等权，确认区留白松散 | 左侧时间地点与参与安排，右侧只读身份及报名；栏目自然高度 |
| 信息字号与基线不一致 | NJU Serif 标题、NJU Sans 正文；正文 16px、时间 20px、状态 13–14px |
| 记录的辅助操作占据大面积底板 | 紧凑事实、原有状态进度、原生 Disclosure 按需展开 |
| 心愿清单与普通卡片难区分 | 信笺、书签、邮票语汇；空态返回班次，不暗示预留名额 |
| 日期切换与详情可能不同步 | 同步选中班次和 URL，日期键盘操作不抢焦点 |
| 客户端根据活动类型推断成功 | 依据报名接口结果；结果不确定时本页锁定重复提交，先查记录 |
| 刷新可能清掉本地输入 | 仅对仍被服务端允许的操作保留草稿、文件、展开状态和焦点 |

## 页面与样式责任

- `ordinary-sessions.js`：普通活动多日期、多场馆的 Session Option；献血车继续使用 `blood-calendar.js` 周日历，不混合两种筛选模型。
- `booking-presentation.js`：选中班次摘要、只读参与者身份、心愿信笺、刷新后的本地输入恢复。
- `pages/workflow-events.js`：复用既有接口和认证，组织确认与参与记录；继续使用 `registrationPresentation()`，不新增业务状态机。
- `booking.css`：页面最大宽度 1480px、普通班次、确认区、事务记录、心愿清单。确认区 1000px 以下堆叠，700px 以下收紧边距和班次布局。
- `calendar.css`：仅周日历；`refinement.css` 不再重复定义报名页宽度、确认区和参与须知。

Canvas、操作强调色、辅助纸面跟随 dawn / sail / garden / iris / amber；可报名、待审核、已报名仍用稳定语义色及文字。小号成功/警告标签在本工作区加深前景以满足对比度要求。正文、操作和邮箱不使用艺术字体；不增加外部字体、框架或动画依赖。

## 业务保护

1. 报名保留须知门禁与 `{consent:true}`，提交期间防止重复点击和刷新干扰。
2. 服务端返回报名成功才显示成功；待确认显示已提交。响应不确定不宣称失败，已提交但刷新失败不诱导再次报名。
3. 请假/取消仍要求原因并等待审批；签到仍限制 JPEG/PNG/WebP、4MB，上传成功只表示等待核验。
4. 名额、截止、冲突、签到资格、时长规则、权限、心愿提醒接口均不改变；不新增数据库行列。
5. 刷新仅保留新状态中仍存在的操作输入；撤销资格或退出会话后不恢复不可用操作。

## 回归与视觉证据

`tests/browser/booking-workspace.spec.mjs` 使用合成身份和拦截接口，不读取生产个人资料、不报名、不发送邮件。覆盖日期焦点、选中与已报名并存、满额/关闭、单次请求、服务器结果、失败刷新、取消原因、照片类型/大小、输入保留及心愿空态。

视觉矩阵保存于 Playwright 测试附件：1280×800、1440×900、1600×900、1920×1080；五主题确认区；未勾选/已勾选；多条记录及展开态；心愿有/无；长标题/地名；390px 手机及 reduced-motion。五主题运行 axe 的 WCAG A/AA 自动规则检查，自动结果不等价于完整人工无障碍认证。

125% / 150% 使用等效 CSS 视口验证重排，不声称完成真实浏览器菜单缩放或辅助阅读器人工测试。页面内刷新保留输入，不承诺硬刷新/离开页面后恢复文件。真实邮件投递、审批和签到核验属于独立业务验收，不由合成 UI 回归证明。
