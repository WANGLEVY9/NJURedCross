# 终审财务工作台（2026-10-26）

版本 3 的终审、财务查看与打款身份进入四个表格工作区：全部条目、活动终审、待打款、报销单记录。初审仍使用原申请审核界面。全部条目按具体支出分行，默认按活动类别和活动分组；待打款默认按活动和稳定申请人账号二级分组，同名申请人不会合并身份。筛选、条目数和金额合计使用同一份结果。

本轮使用活动类别（活动目录的 `category/type`；缺失时显示未分类），不新增报销类别规则，不实现预算上限。个人银行卡不再展示或填写；报销表使用固定单位和经费账户。活动信息默认折叠，经办人与联系电话从可信账号读取；模拟账号缺少联系电话时需要补齐。

## 条目、材料和金额

- 条目稳定标识为 `(requestId, itemId)`；保留原申请、申请人、原活动、原件与材料版本。
- 尚未终审的条目可以单独调整所属报销活动；材料仍按原条目关联读取，已生成的旧草稿通过申请状态版本校验失效。已终审条目不能移动。
- 活动终审在一张表中勾选条目、填写核定金额和原因、上移/下移、查看材料。生成报销表与证据材料使用相同条目顺序，共用材料在本批末尾附一次。分活动生成时，各批保留需要的共用证据。
- 原申请金额不被核定金额覆盖。核定金额只能减少，减少必须有原因；生成的报销表采用核定金额。
- 同一份申请可分活动、分批完成条目终审。申请只有在所有条目终审完毕后才整体成为 `approved`；工作台按每个条目呈现真实阶段。
- 已终审条目的名称、原金额、用途和标识在后续初审修改、申请人补充时冻结；尚未终审条目仍可走退回流程。旧终审材料保留在原报销单中。
- 核验提示只读取已有识别结果，不在列表加载时重新识别或加载图片/PDF。未知结果仍提示人工核对。

## 材料提交、经费到账与个人打款

生成材料不等于已经提交校医院。终审通过后，报销单记录分别登记材料提交日期、经费到账日期和实际到账金额。只有完成到账登记的条目才允许登记打款。

到账总额少于核定总额时，必须完整填写本批各条目的实际可支付金额及差额原因，分配合计必须精确等于实际到账金额，每项不能超过原核定金额。原申请、核定与到账分配分别保存。

单项或批量打款登记都需要实际打款日期、手动确认的实际总额及完成确认；打款人从当前账号记录，默认日期为当天。批量金额须精确等于所选条目的实际应付合计。不符时不改变任何条目，须回到到账分配核查差额后再登记。此功能记录外部已经完成的支付，不执行银行转账。零金额的核减条目也保留结清登记。

每次变更有版本检查。打款以幂等操作标识防止重试或并发重复登记；本批已有打款记录后，到账分配不能再修改。报销单可展开查看材料版本、提交和到账登记、打款合计及归档 PDF。一个活动出现多个阶段时，分别显示各阶段条目数。

## 接口与存储

接口前缀为 `/api/reimbursements`，隔离本地服务也可使用 `/api/preview/reimbursements`。所有写操作保持会话、CSRF 和服务端权限检查。

| 接口 | 用途 |
| --- | --- |
| `GET /finance` | 返回条目、活动、报销单元数据及当前操作人；不下载 PDF 对象 |
| `POST /finance/move` | `{selections:[{requestId,itemId,revision,stateVersion}],activityId}` |
| `POST /summaries` | 原接口增加 `selections[].itemIds` 和可选 `settlements:[{requestId,itemId,amount,reason}]` |
| `POST /summaries/:id/review` | 原活动终审接口，条目范围和材料版本均受校验 |
| `POST /finance/summaries/:id/funding` | `{stateVersion,submittedDate,receivedDate?,receivedAmount?,allocations?,note?}`；分配项为 `{requestId,itemId,amount,reason}` |
| `POST /finance/payments` | `{selections,amount,paidDate,confirmed,idempotencyKey,reference?,note?}` |

数据继续使用既有 NJUTable 事务日志和 NJUBox 对象机制：逐项归属、终审和支付信息放在申请的 `financeItems`；到账分配、进程、修改历史放在汇总记录。无需新增真实表或列。现有报销记录表的备注投影同步提交日期、到账金额和打款摘要，详细历史以事务日志为准。旧版逐份打款接口不允许绕过版本 3 的到账登记要求。

Excel 继续支持总表与明细；明细新增条目所属活动、活动类别、核定金额、实际可支付金额、逐项已打款金额和差额原因。原申请总额与整体打款总额只在首行列出，逐项金额另列，避免重复累计。
